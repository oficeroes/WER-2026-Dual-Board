# 01 · 原理与改动点

> 读者：想弄清「为什么能用」的老师 / 技术同学。
> 结论先行：我们**没有改项目文件、没有改新建项目模板**，而是把函数库编译成 IDE 资源包里的「原生积木」——IDE 自己就会渲染它们、自己就会生成 Python。

---

## 1. 用户需求与方案选择

需求原话：「可不可以你提前写好一些函数，然后当我打开这个 IDE 的积木编程时，就能直接在函数上看到这些积木块，直接拖下来就能用？」

| 方案 | 做法 | 结果 |
| --- | --- | --- |
| 旧方案：模板注入 | 改新建项目默认模板，往新项目里塞函数定义 | 已弃用：用户要的是**内部渲染的原生积木**，不是把 XML 塞进项目 |
| 现方案：原生积木 | 把函数库编译进 IDE 内部资源包：新增 toolbox 分类 + 注册 `Blockly.Blocks`/`Blockly.Python` + 生成 Python 时条件注入 `def` | **采用**：左侧直接出现「我的函数」分类，块是 IDE 真原生块；工程不含原生块时输出与官方逐字节一致 |

关键区别：原生积木的**块定义**在 IDE 的 JavaScript 环境里注册，属于 IDE 运行时的一部分；所以新建项目、打开旧项目都能看到，不需要任何项目级准备。

---

## 2. 涉及的 IDE 内部结构（前提知识）

AbilixScratch3.0 的积木页面是一个打包在 `browser_assets` 里的 Blockly Web 应用：

```
D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets
└─ 自定义 zfbRes_v1 归档（无压缩），6645 个条目：
   ├─ /Blockly_Code/maingui.html          ← 积木页面外壳
   ├─ /Blockly_Code/maingui.js            ← 页面主逻辑（含 getPythonCode）
   ├─ /Blockly_Code/generators/*.js       ← 各积木的 Python 生成器
   ├─ /Blockly_Code/toolbox_*.xml?        ← 工具箱 XML 内嵌在 maingui.html 里
   └─ 其它 JS/CSS/图片/字体…（完整细节见 03 文档）
```

要点：

1. `browser_assets` 是 IDE 启动时读取的**只读资源包**（Program Files 下，普通用户只读；改它需要管理员）。
2. `maingui.html` 里按机器人型号内嵌了 3 个工具箱 XML：`toolbox_skcon9`、`toolbox_skcon5`、`toolbox_skcon2`（SKCON9 = 普及赛用机器人）。左侧分类由这些 XML 渲染。
3. 函数分类的规则：工程工作区里有 `procedures_defnoreturn` 定义时，左侧「函数」分类的 flyout 会自动出现对应调用块。**但这是「项目内」函数，只存在于当前工程**；我们做的是把函数预先注册成全局块类型。
4. `maingui.js` 的 `getPythonCode(robotType, connectionType, programName)` 负责把积木工作区生成 Python：文件头 → import → `robot = Robot()` → … → `def main():` → 各积木生成的语句。

## 3. 本方案改了哪 4 个地方

补丁只动 `browser_assets` 内的 **4 个条目**，其它 6643 个条目逐字节不变（自检强制校验）：

| # | 条目 | 改动 | 作用 |
| --- | --- | --- | --- |
| 1 | `/Blockly_Code/maingui.html` | ① 在 `myrobotpythoncode.js` 的 `<script>` 后插入 `<script src="abilix_userlib.js"></script>`；② 在 3 个机器人工具箱 XML 末尾各插入一个 `<category name="我的函数" colour="#9933FF">`，内含该型号可用的函数块 | 让页面加载新 JS；让左侧出现「我的函数」分类 |
| 2 | `/Blockly_Code/abilix_userlib.js`（**新增**） | 注册 `Blockly.Blocks['abilixuf_<函数名>']`（外形/参数槽/颜色/提示）与 `Blockly.Python['abilixuf_<函数名>']`（生成 `func_名字(...)` 调用）；携带 `abilixUserLibPython`（函数定义 prelude 文本）与 `abilixUserLib`（函数元数据） | 积木「长什么样」「被拖出来时算哪种块」「生成什么代码」 |
| 3 | `/Blockly_Code/maingui.js` | 在 `getPythonCode` 拼接代码的两处，把 `Blockly.Python.workspaceToCode(workspace) +` 改成**条件注入**：只有当前工程里存在 `abilixuf_*` 块时，才把 `abilixUserLibPython`（函数定义）插到生成代码之前 | 让右侧 Python 自动带上 `def func_xxx(...)`，且**不含原生块的项目完全不受影响** |
| 4 | `/Blockly_Code/abilix_userlib.json`（**新增**） | 补丁清单/清单文件：工具版本、构建时间、函数库路径/hash/函数列表/prelude hash、原始资源包信息、4 个条目的 size/sha256 | 状态检查、是否需要重装、还原前核对 |

条件注入的实际代码（第 3 条，替换 `maingui.js` 中恰好 2 处）：

```js
((typeof abilixUserLibPython !== "undefined" &&
  workspace && workspace.getAllBlocks &&
  workspace.getAllBlocks().some(function(b){ return (b.type||"").indexOf("abilixuf_")===0; }))
    ? abilixUserLibPython : "") +
Blockly.Python.workspaceToCode(workspace) +
```

→ 工程里有 `abilixuf_` 原生块 ⇒ 注入函数定义；没有 ⇒ 注入空串，输出与官方**逐字节一致**。这是本方案最重要的兼容性设计。

## 4. 编译流程（`原生积木核心.py` 在做什么）

```
我的函数库.srhs
   │  ① 解析（srhs工具.py）：取所有 procedures_defnoreturn 定义 → 名字/参数/注释
   ▼
函数清单（name, args, blockType=abilixuf_<name>, tip）
   │  ② 生成 prelude：解包原始 browser_assets → 用无头 Chrome 跑 IDE 的真实
   │     Blockly 引擎加载函数库工程 → 调用 IDE 自己的 getPythonCode →
   │     截取「robot = Robot() 之后、def main() 之前」的全局变量 + def 函数定义
   ▼
prelude（函数定义 Python 源码）
   │  ③ 生成 abilix_userlib.js：块定义 + Python 生成器 + prelude + 元数据
   │  ④ 生成分类 XML，插进 3 个 toolbox；插入 script 标签
   │  ⑤ 改 maingui.js：两处条件注入
   ▼
重新打包 zfbRes_v1：原条目顺序 + 追加 userlib.js、userlib.json
   │  ⑥ 自检 verify：条目数/顺序/新增集合/逐字节比对
   ▼
browser_assets（补丁包，不写安装目录）→ install 时原子替换到真实路径
```

为什么 prelude 要用「真实引擎」生成：函数体里可能有 IDE 自己的特殊生成规则（clamp、global 声明、变量初始化、定时器、`robot` API 参数顺序等）。用 IDE 自己的生成器算出来的定义，才能保证拖块生成的调用与定义**完全一致**，不用手工维护第二套规则。
> **安装为什么分两段**：浏览器无头模式在**管理员提权进程**里会失效（实测本机 Chrome 157：启动约 80ms 即退出、不产出 DOM，引擎生成直接失败）。所以 `安装原生积木.cmd` 先在**普通权限**下跑 `install --compile-only` 生成补丁包，再弹 UAC 只用管理员权限跑 `install --prebuilt` 做替换——编译和提权彻底分开，安装才稳定。

## 5. 本机实际改动规模（1 个函数库版本）

以本机（1.0.3.4）实测数据：

| 指标 | 原版 | 打补丁后 |
| --- | --- | --- |
| 资源包大小 | 85,271,033 B（81.3 MB） | 85,274,935 B（+3,902 B） |
| 资源包 sha256 | `df6db241752d42bff2995fcd24521e070adf9eb5d96e870148f9dc51690edc40` | 随函数库变化（例：`17ed1363…`） |
| 条目数 | 6645 | 6647（+2） |
| `maingui.html` | 69,281 B | 69,853 B（+572） |
| `maingui.js` | 23,313 B | 23,733 B（+420） |
| 新增 `abilix_userlib.js` + `abilix_userlib.json` | — | 合计约 2.9 KB |
| 其它 6643 个条目 | — | **逐字节不变** |

> 补丁大小主要由 prelude 决定：1 个函数的库约 +3.9 KB；20 个函数/27 个变量的库，prelude 为 14,064 字符。资源包总增量仍在几十 KB 级别，对 IDE 启动无感。

## 6. 兼容性与回归（为什么可以放心用）

自动化验证（真实解包资源 + 真实 Blockly 引擎 + 无头 Chrome，证据在 `WER_函数库/证据/原生积木验证/`）：

| 场景 | 结果 |
| --- | --- |
| 不含原生块的**真实用户工程** PI.srhs 在打补丁后生成 Python | 50,618 B，sha256 `30a0bab0…`，与官方黄金样本 `逆向资料/样本程序/PI.py` **逐字节一致** |
| 不含原生块的工程（PI 项目） | 不注入 prelude，逐字节一致 |
| 含 1 个原生块的最小工程 | 32/32 断言通过；生成 203 B，与手工预期逐字节一致；prelude 61 字符 |
| 含 20 个原生块（含 11 个带参）的工程 | 32/32 断言通过；生成 15,544 B；调用/参数/prelude 位置/py_compile 全对 |
| 未打补丁的旧工具箱、旧参数/拖拽模式 | 16/16、13/13 通过（向后兼容） |
| 误在无 `userlib.js` 的资源上跑原生验证 | 明确报错退出 2，不会静默出错 |

也就是说：**装了补丁的 IDE，普通积木的生成结果和原版一模一样**；只有工程里真的拖了「我的函数」的块，才会多出函数定义。

## 7. 设计边界（为什么不做成别的样子）

1. **不改 `.srh`/`.srhs` 工程文件格式**：工程仍是官方格式，随时可以交给未打补丁的电脑（但原生块会缺，见下）。
2. **不改新建项目默认模板**：旧模板注入方案会让每个新项目都带一大堆函数定义，且不是原生块；已弃用。
3. **不手工改 `browser_assets` 的其它内容**：逐字节自检保证只有 4 个预期条目变化，避免引入未知风险。
4. **备份先行**：安装前自动把原始资源包备份到 `WER_函数库\工具\原生积木\备份\browser_assets.原始.<sha12>.bin`，还原只认这份备份。
5. **版本绑定**：工具内置本机原版资源包的 sha256（1.0.3.4）。换了软件版本会警告但仍可编译（会先备份新版本资源包）。跨版本时**不要用旧版本的备份去还原新版本软件**（详见 04 文档）。

已知限制（用之前要知道）：

- 界面不能新建带参函数（官方屏蔽了参数 mutator）→ 从示例库复制带参函数再改名。
- 原生块类型与**函数名绑定**：改名后旧工程里的旧块失效。
- 用原生块保存的工程，在未打补丁的电脑上打开会显示未知块/缺块。
- 构建/安装需要本机有 Chrome 或 Edge（生成 prelude 用）；
- 安装需要管理员权限，并需要先关闭 IDE。
