## 1. 资源包 `browser_assets` 的二进制格式（zfbRes_v1）

IDE 的 Web 资源都打包在一个自定义归档文件里：

```
D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets
```

格式（C# 侧用 `BinaryWriter` 写，工具用 `工具/底层/patch_browser_assets.py` 读写）：

```
[字符串 "zfbRes_v1"]            ← .NET BinaryWriter 的 7-bit 长度前缀 + UTF-8 字节
[int32  条目数 N]
[条目 1] ... [条目 N]           ← 索引区
[数据区]                        ← 各条目原始字节按索引顺序连续存放

每个条目索引：
[字符串 条目名]                  ← 例如 "/Blockly_Code/maingui.html"
[int64  数据区中的绝对 offset]
[int32  数据长度]
```

- 无压缩、无对齐、条目名以 `/` 开头的虚拟路径。
- 本机原版：**85,271,033 字节，6645 个条目**，sha256 `df6db241752d42bff2995fcd24521e070adf9eb5d96e870148f9dc51690edc40`。
- 工具内置这两个「本机原版」常量（`ORIGINAL_ASSETS_SHA` / `ORIGINAL_ASSETS_SIZE`），用于判断「原版 / 已打补丁 / 未知版本」。

常用条目：

| 条目 | 说明 |
| --- | --- |
| `/Blockly_Code/maingui.html` | 积木页面外壳：CSS/JS 引用 + 3 个内嵌工具箱 XML（`toolbox_skcon9/5/2`） |
| `/Blockly_Code/maingui.js` | 页面主逻辑，含 `getPythonCode(robotType, connectionType, programName)` |
| `/Blockly_Code/generators/myrobotpythoncode.js` | Python 生成规则总表（也是本方案的脚本插入锚点） |
| `/Blockly_Code/generators/*.js` | 各积木生成器 |
| `/Blockly_Code/abilix_userlib.js` | **本方案新增**：原生函数积木定义 + prelude |
| `/Blockly_Code/abilix_userlib.json` | **本方案新增**：补丁清单 |

## 2. 函数库的来源：`.srhs` / `.srh`

`我的函数库.srhs` 是 zip，唯一成员 `abilixProject.srh`，zip comment 是机器人型号数字（111=SKCON9、110=SKCON5、112=SKCON2）。

`.srh` 文本结构：

```
<Abilix.ScratchProject.Info>
{Info XML：工程名/机器人类型/版本…}
</Abilix.ScratchProject.Info>

<Abilix.ScratchProject.ProjectString>
{Blockly 项目 XML}
</Abilix.ScratchProject.ProjectString>
```

工具用 `工具/底层/srhs工具.py` 的 `read_project_file` / `find_def_blocks` 提取所有 `procedures_defnoreturn` 定义：

- 函数名：定义块里的 `NAME` 字段；
- 参数：`<mutation><arg name="cm">…` 的顺序列表；
- 函数体：`STACK` 子块（用于真实引擎生成 Python）；
- 注释：定义上的 `annotation` 文本 → 作为积木 tooltip。

校验规则（任一不满足即 `✘ 失败`，退出码 2）：

| 规则 | 报错（节选） |
| --- | --- |
| 文件存在 | `函数库文件不存在：…` |
| 至少 1 个函数定义 | `函数库里没有函数定义（procedures_defnoreturn）…` |
| 函数名非空、合法 Python 标识符 | `函数名 %r 不是合法的 Python 标识符…请回到 IDE 里重命名后重新保存函数库。` |
| 无重名 | `函数库里有重名函数：…` |
| 积木类型不冲突 | `函数名 %r 与另一个函数在积木类型上冲突（%s）。` |
| 参数名合法 | `函数 %s 的参数名不是合法 Python 标识符：…` |

积木类型由函数名派生：

```python
BLOCK_TYPE_PREFIX = 'abilixuf_'
block_type_of(name) = 'abilixuf_' + re.sub(r'[^A-Za-z0-9_]', '_', name)
```

→ `func_Hello` ⇒ `abilixuf_func_Hello`。**改名 = 换积木类型 = 旧工程旧块失效。**

## 3. 新增条目 1：`/Blockly_Code/abilix_userlib.js`

生成函数 `build_userlib_js()`，文件骨架（`<…>` 为生成内容）：

```js
/* AbilixScratch3.0 原生函数积木 —— 由「WER_函数库/工具/原生积木/原生积木核心.py」自动生成，请勿手改。 */
var abilixUserLibPython = "<prelude 的 JSON 字符串>";
var abilixUserLib = [ { "name": "func_Hello", "args": [], "tip": "…", "blockType": "abilixuf_func_Hello" }, … ];
(function () {
  function label(s) { return String(s == null ? "" : s); }
  for (var i = 0; i < abilixUserLib.length; i++) {
    (function (fn) {
      var type = "abilixuf_" + fn.name.replace(/[^A-Za-z0-9_]/g, "_");
      fn.blockType = type;
      Blockly.Blocks[type] = {
        init: function () {
          this.appendDummyInput().appendField(label(fn.name));   // 块上显示函数名
          this.setPreviousStatement(true, null);                 // 可接上一块
          this.setNextStatement(true, null);                     // 可接下一块
          for (var a = 0; a < fn.args.length; a++) {             // 每个参数一个值输入槽
            this.appendValueInput("ARG" + a).setCheck(null).appendField(label(fn.args[a]));
          }
          this.setInputsInline(false);                           // 参数竖排
          this.setColour(290);                                   // 紫色系
          this.setTooltip(label(fn.tip || fn.name) + "（来自我的函数库）");
          this.setHelpUrl("");
        }
      };
      Blockly.Python[type] = function (block) {                  // 生成调用代码
        var parts = [];
        for (var a = 0; a < fn.args.length; a++) {
          parts.push(Blockly.Python.valueToCode(block, "ARG" + a, Blockly.Python.ORDER_NONE) || "");
        }
        return fn.name + "(" + parts.join(", ") + ")\n";
      };
    })(abilixUserLib[i]);
  }
})();
```

要点：

- **块定义**在真实 Blockly 环境里注册 → IDE 会把它当原生块渲染、序列化到工程 XML（`type="abilixuf_func_Hello"`）、加载旧工程时能识别。
- **Python 生成器**只生成一行调用 `func_xxx(实参, …)`；函数定义本身不在这里，而是由 `getPythonCode` 条件注入（见 §6）。
- prelude/meta 用 `json.dumps(ensure_ascii=False)` 生成，中文注释/tooltip 不会乱码；`</` 做转义避免提前闭合脚本。
- 参数槽名固定 `ARG0/ARG1/…`，与分类 XML 的 `<value name="ARG0">` 一致。

## 5. `maingui.html` 的两处补丁

函数 `patch_html(html, category_xml)`：

### 5.1 插入脚本标签

锚点（必须恰好出现 1 次，否则报数量异常）：

```html
<script src="generators\myrobotpythoncode.js"></script>
```

在其后插入：

```html
<script src="abilix_userlib.js"></script>
```

若源 HTML 已含该脚本行 → 报「源资源包可能已打过补丁」。

### 5.2 给 3 个机器人工具箱加分类

在 `maingui.html` 中找所有 `<xml id="toolbox_skcon\d" …>`，在对应 `</xml>` 前插入分类 XML；必须恰好 3 个（SKCON9/5/2），插入后再次校验 `name="我的函数"` 出现 3 次。

分类 XML（`build_category_xml()`）：

```xml
   <category name="我的函数" colour="#9933FF">
      <sep gap="8"></sep>
      <block type="abilixuf_func_Hello"></block>
      <sep gap="8"></sep>
      <block type="abilixuf_func_ForwardCM">
        <value name="ARG0"><shadow type="math_number"><field name="NUM">0</field></shadow></value>
      </block>
      <sep gap="8"></sep>
      …
   </category>
```

- `<shadow type="math_number">` → 参数槽默认带一个「0」数字块，拖出来即可填数；
- 无参函数只有 `<block type=…></block>`；
- 每个块之间 `<sep gap="8">`，分类用 `#9933FF` 紫色，与 JS 里 `setColour(290)` 呼应。

## 6. `maingui.js` 的条件注入（兼容性关键）

函数 `patch_js(js)`：源 `maingui.js` 中 `\t\tBlockly.Python.workspaceToCode(workspace) +` 必须**恰好出现 2 处**（两处代码拼接点），否则拒绝（说明源包不是预期版本）。替换为：

```js
		((typeof abilixUserLibPython !== "undefined" && workspace && workspace.getAllBlocks &&
		  workspace.getAllBlocks().some(function(b){return (b.type||"").indexOf("abilixuf_")===0;}))
			? abilixUserLibPython : "") +
		Blockly.Python.workspaceToCode(workspace) +
```

- **只有当前工程工作区里存在 `abilixuf_*` 块**，才把 prelude（函数定义）拼到生成代码前面；
- 否则拼空串 → 生成结果与官方完全一致（这是 PI 回归能逐字节一致的原因）；
- 补丁后自检：`abilixUserLibPython` 在源码中出现 **4 次**（2 处 `typeof` + 2 处引用），否则报错。

## 7. prelude 的生成与提取

`build_prelude()`（在 `build`/`install` 里调用；`--prelude-in` 可跳过）：

1. 用 `patch_browser_assets.py` 把**原始资源包**解包到临时目录（≈80 MB、6600 条目）；
2. 调用 `工具/验证/run_validate.py`：

```
python run_validate.py <函数库.srhs> --web-root <解包目录>
    --py <临时生成.py> --json <临时结果.json>
    --timeout <秒> --window-size 1600,1800 --work-dir <临时目录>
```

它用 **无头 Chrome** 加载解包出的真实 Blockly 页面，调用 IDE 自己的 `maingui.getPythonCode` 生成函数库工程的 Python；
3. `extract_prelude()` 截取：

```
起点：'robot = Robot()\n' 之后
终点：'\n\ndef main():' 之前
```

即「全局变量声明 + 全部 `def func_xxx(...)`」，strip 首尾空行后追加 `\n\n`。

防呆校验（任何一条不满足即失败）：

| 校验 | 目的 |
| --- | --- |
| prelude 不含 `import` / 文件头 `#<` / `robot = Robot()` 行 | 防止把头部重复注入 |
| 每个函数名都出现 `def <name>(` | 防止引擎生成不完整 |
| `compile(prelude, ...)` 语法自检 | 保证注入后工程可编译 |

失败提示：`真实引擎生成函数库 Python 失败…打补丁的电脑需要有 Chrome 或 Edge（本机两者其一即可）。`

> 注意：`prelude` 是**构建产物**，随函数库变化；它不手工维护、也不从工程文件里读。

## 8. 打包与自检规则

`_pack_zfb()`：条目顺序 = **原索引顺序不变**，末尾追加 `abilix_userlib.js`、`abilix_userlib.json`；数据区按顺序连续重排（无压缩）。

`verify_package(补丁包, 原始包)` 校验：

1. 补丁包是合法 zfbRes_v1；
2. 前 N 个条目名/顺序与原始包完全一致；
3. 新增条目集合恰好 = `{abilix_userlib.js, abilix_userlib.json}`；
4. 原条目中**只有** `maingui.html`、`maingui.js` 允许且必须变化（各 1 个）；
5. 其余条目逐字节不变（统计 `unchanged`）；
6. 任何一项不符 → `build` 失败（`补丁包自检失败：…`）。

成功日志：

```
    修改 /Blockly_Code/maingui.html（69281 -> 69853 字节）
    修改 /Blockly_Code/maingui.js（23313 -> 23733 字节）
    新增 /Blockly_Code/abilix_userlib.js（… 字节）
    新增 /Blockly_Code/abilix_userlib.json（… 字节）
    其余 6643 个条目逐字节不变
```

## 9. 路径与依赖（为什么换电脑必须整目录拷贝）

`原生积木核心.py` 用「相对自身位置」推导所有路径：

```python
HERE       = <WER_函数库>/工具/原生积木
TOOL_DIR   = <WER_函数库>/工具
LIB_ROOT   = <WER_函数库>
REPO_ROOT  = <WER_函数库> 的上一级
BOTTOM_DIR = <WER_函数库>/工具/底层     # sys.path.insert → import patch_browser_assets / srhs工具
VERIFY_DIR = <WER_函数库>/工具/验证     # run_validate.py
```

默认值：

| 参数 | 默认 |
| --- | --- |
| 安装目录 | `D:\Program Files\AbilixScratch3.0` |
| `assets` | `<安装目录>\AbilixScratch3.0_Data\Resources\browser_assets` |
| 函数库 | `<WER_函数库>\我的函数库.srhs` |
| 备份目录 | `<WER_函数库>\工具\原生积木\备份` |
| 构建临时目录 | `<REPO_ROOT>\_分析临时\native_work\build` |

→ **只拷贝 `工具\原生积木\` 三个文件是不够的**：`工具\底层\`（zfb 打包、srh 解析）与 `工具\验证\run_validate.py` 必需；整个 `WER_函数库` 目录一起拷贝最稳。

## 10. 状态与退出码

`status` 的 JSON（`--json` / `--json-out`）字段：`assets`、`library`、`backupDir`、`assetsExists`、`admin`、`ideRunning`、`patched`、`needSync`、`recommend`、`errors`、`assetsSize`、`assetsSha256`、`original`、`backups`、`manifest`、`patchedLibrary`（`sha256`/`defs`）、`builtAt`、`libraryExists`、`librarySha256`、`defsDiff`（`{old,current,same}` 或 `{error}`）。

退出码约定：

| 码 | 含义 |
| --- | --- |
| 0 | 成功（含 `status` 无错误、`verify` 通过） |
| 1 | `status` 发现错误 / `verify` 失败 |
| 2 | 参数错误或运行失败（`✘ 失败：…`，如需要管理员、IDE 运行、函数库非法、引擎失败） |

`verify` 输出：`校验结果：通过 ✔` / `失败 ✘`，列出修改/新增条目与「其余 N 个条目逐字节不变」。

## 11. 安全与原子性

- **安装**：先 `backup_original()`（复制到备份目录并校验 sha）→ 在临时文件 `.browser_assets.wer_native.<pid>.tmp` 写好 → `os.replace` 原子替换 → 回读 sha256 与 manifest 校验。
- **还原**：`find_original_backup()` 优先选「本机记录的原版 sha」的备份；备份 sha 不等于本机记录原版时需 `--force`。
- **IDE 运行检测**：`tasklist` 匹配 `abilixscratch*` 进程；运行中默认拒绝安装/还原（`--force` 可跳过）。
- **备份命名**：`browser_assets.原始.<sha前12位>.bin`（幂等，已存在不覆盖）；`list_backups` 只认这一命名，所以 `备份\我的函数库.srhs.bak-…` 这类文件不会计入备份数。

## 12. 可复现的构建/校验命令

```bat
:: 只编译，不碰安装目录（输出补丁包 + 可选把解包 web 目录给验证工具用）
python WER_函数库\工具\原生积木\原生积木核心.py build ^
  --library WER_函数库\我的函数库.srhs ^
  --source-assets "D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets" ^
  --out _分析临时\browser_assets_patched.bin ^
  --web-out _分析临时\native_work\patched_web

:: 独立校验补丁包（条目数/顺序/逐字节）
python WER_函数库\工具\原生积木\原生积木核心.py verify ^
  --file _分析临时\browser_assets_patched.bin ^
  --original "D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets"

:: 在临时副本上演练安装（不碰真实安装目录）
python WER_函数库\工具\原生积木\原生积木核心.py install --dry-run

:: 解包任意资源包（查看/对照条目）
python WER_函数库\工具\原生积木\原生积木核心.py extract-web ^
  --assets "D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets" ^
  --out _分析临时\web_unpacked
```

高级参数：`build --prelude-out/--prelude-in`（复用已生成的函数定义，跳过浏览器引擎，适合无 Chrome 的机器做二次构建）、`--json-out`（机器可读结果）、`--keep-work`（保留临时目录）。

## 13. 实现约定（改代码时注意）

1. 源码/资源 UTF-8；`maingui.js` 的替换串带 **2 个制表符缩进**，不要改成空格，否则匹配失败。
2. 三个锚点/计数都是硬校验：script 锚点 1 处、toolbox 3 个、`workspaceToCode` 2 处、补丁后 `abilixUserLibPython` 4 处。源资源包不是本机 1.0.3.4 时，这些计数可能变化 → 先 `extract-web` 核对再改。
3. 分类 XML 插在 `</xml>` 前（不是工具箱全部内容之后），保证 XML 合法。
4. 新增条目只能追加在索引末尾；不要重排原条目顺序（C# 读取按索引名查找，但顺序变化会破坏逐字节自检）。
5. 不要修改 `工具/底层/patch_browser_assets.py` 的 zfb 读写格式；它同时被 `工具/验证/run_validate.py` 使用。
