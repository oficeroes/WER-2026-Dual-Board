# 04 · 回滚与升级重打

> 读者：装过补丁、之后要还原 / 升级软件 / 换函数库的老师或技术同学。
> 一句话原则：**原始资源包备份是唯一的「后悔药」，任何操作之前先确认它在不在。**

---

## 1. 安装/还原前后到底发生了什么

| 操作 | 工具行为 |
| --- | --- |
| `install`（首次，原版资源包） | 把原版复制到 `工具\原生积木\备份\browser_assets.原始.<sha前12位>.bin` → 编译 → 原子替换真实 `browser_assets` → 回读校验 |
| `install`（已是补丁版） | 用备份的原版重新编译（找不到备份会报错要求 `--source-assets` 或先 `restore`）→ 替换 |
| `restore` | 找备份（优先「本机记录的原版 sha」的那份）→ 校验 → 原子替换回原版 |
| `status` | 只读：不写任何文件 |

替换采用「临时文件 + `os.replace` 原子替换」，中途断电不会留下半个文件（最坏情况是真实文件未变）。

## 2. 回滚（还原原版）

### 2.1 标准做法（推荐）

1. 关闭 AbilixScratch3.0（任务管理器确认 `AbilixScratch3.0.exe` 不在）；
2. 双击 `WER_函数库\工具\原生积木\还原原版.cmd`；
3. UAC 点「是」；
4. 看到：

```
还原完成 ✔
  资源包：D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets
  sha256：df6db241752d42bff2995fcd24521e070adf9eb5d96e870148f9dc51690edc40（与本机记录的原始包一致）
```

即恢复成功。打开 IDE，「我的函数」分类消失，一切回到安装前。

### 2.2 先演练再动手

不确定备份对不对时，先跑 dry-run（**不修改真实安装目录**，在临时副本上走完整流程）：

```bat
cd /d <WER_函数库 所在目录>
python 工具\原生积木\原生积木核心.py restore --dry-run
```

### 2.3 指定某一份备份 / 强制还原

```bat
python 工具\原生积木\原生积木核心.py restore --from-backup "工具\原生积木\备份\browser_assets.原始.df6db241752d.bin"
```

- 备份的 sha256 **不等于**本机记录的原版 sha 时会拒绝，确认无误可加 `--force`；
- IDE 还在运行时默认拒绝，确认要冒险可加 `--force`（不建议）。

### 2.4 备份文件在哪、长什么样

```
WER_函数库\工具\原生积木\备份\
└─ browser_assets.原始.df6db241752d.bin      ← ~81 MB，本机 1.0.3.4 原版
```

- 命名固定为 `browser_assets.原始.<原包 sha256 前 12 位>.bin`；
- `status` 里的「备份 N 份」**只统计这种命名的文件**（`我的函数库.srhs.bak-…` 之类不算）；
- **不要删**：重装、还原、升级重打都靠它。删了之后要找回原版，只能靠软件修复安装/重装，或从另一台同版本电脑复制（sha 必须一致）。

### 2.5 备份丢了怎么办

按优先级：

1. **软件修复安装/重装**（官方安装包，恢复原版 `browser_assets`）；
2. 从另一台**同版本、未打补丁**的电脑复制 `...\Resources\browser_assets`（校验 sha 应为 `df6db241…edc40`），再运行一次 `install`（工具会重新备份并打补丁）；
3. 如果只是想「不要补丁」：直接从另一台同版本电脑复制原版文件覆盖（管理员），或重装软件。

## 3. 改了函数库之后（最常见的「重打」）

1. 在 IDE 里编辑 `WER_函数库\我的函数库.srhs` → `Ctrl+S` 保存；
2. **关闭 IDE**；
3. 双击 `安装原生积木.cmd` → UAC 点「是」；
4. 重新打开 IDE。

工具会自动识别「当前已是补丁版」，用「备份的原版资源包 + 当前函数库」重新编译安装，**不需要先还原**。装完可以：

- `状态检查.cmd` → 「是否需要重装：否（已同步）」；
- 或在命令行 `status --json` 看 `needSync: false`。

### 3.1 提示「当前资源包已打过补丁，却找不到原始包备份」

说明备份被删/被移动了。解决：

```bat
:: 方式 A：先还原（如果还原也报没备份，用方式 B）
python 工具\原生积木\原生积木核心.py restore
:: 方式 B：直接指定一份原始 browser_assets 作为基准
python 工具\原生积木\原生积木核心.py install --source-assets "D:\某个原始备份\browser_assets"
```

### 3.2 函数库改了但 IDE 没变化

- 确认改的是 `WER_函数库\我的函数库.srhs`（不是示例库）；
- 确认保存成功（文件修改时间变化）；
- 确认**重新安装过**且 IDE 重启；
- `状态检查.cmd` 看「是否需要重装」：若是「是（函数库有变化）」→ 重装即可。

## 4. 软件升级 / 重装之后（重点）

### 4.1 升级后补丁会消失

AbilixScratch3.0 升级会用自己的新资源包覆盖 `browser_assets`，补丁随之消失（「我的函数」分类消失）。这是正常的，**重新安装一次即可**：

1. 关闭 IDE；
2. 双击 `安装原生积木.cmd` → UAC 点「是」；
3. 工具会先备份「新版本的原版资源包」（`browser_assets.原始.<新 sha12>.bin`），再编译安装；
4. 如果新版本资源包与开发机 1.0.3.4 不同，编译日志会出现警告：

```
⚠ 注意：这不像本机记录的原始资源包（sha256 不同），但格式合法，继续编译。
```

   能编译成功就可用；如果报错（锚点数量异常等），说明新版本页面结构变了，需要更新工具（找开发同学）。

### 4.2 升级后千万不要直接用旧的「还原原版.cmd」

`restore` 会优先选「本机记录的原版 sha」匹配的备份，也就是**升级前旧版本**的资源包；把旧资源包还原到**新版本软件**上，可能导致 IDE 异常。

升级后如果已经打了补丁、又想回到「新版本原版」：

```bat
:: 1) 找到升级后安装时自动生成的新备份
dir 工具\原生积木\备份

:: 2) 用新备份还原（sha 与记录不同，需要 --force）
python 工具\原生积木\原生积木核心.py restore ^
  --from-backup "工具\原生积木\备份\browser_assets.原始.<新sha12>.bin" --force
```

**更简单的做法**：升级后直接重装软件（官方包）即可回到干净状态；或先确认升级后的「新原版备份」再决定。

### 4.3 旧备份怎么清理

确认新版本已装好、且不再需要回退旧版本后，可以让旧备份留在原处（占约 81 MB/份），也可以手动删除**不匹配当前版本**的旧备份文件；文件命名里带的是资源包 sha 前 12 位，可对照 `status` 输出（「备份 N 份」列表会显示 hash 前缀）。

> 建议保留：当前版本原版 1 份；其它可删。

### 4.4 换安装路径 / 换盘

软件重装到其它路径后，工具默认还找 `D:\Program Files\AbilixScratch3.0`。用 `--assets` 指定：

```bat
python 工具\原生积木\原生积木核心.py install --assets "E:\新路径\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets"
```

或直接修改安装目录后再双击 `.cmd`（`.cmd` 会把参数 `%*` 转发给 install）。

## 5. 换机器人型号（SKCON9 / SKCON5 / SKCON2）

- 补丁已经给 3 个型号的工具箱都加了「我的函数」分类，且块定义是全局的，所以换型号也能用；
- 生成 Python 的机器人 API/文件头由**工程本身**的型号决定，与函数库无关；
- 函数库的 `.srhs` zip comment 记录了建库时的型号（默认 111=SKCON9）；工具会读取并在 manifest 里记录 `robotType`，但**不阻止**跨型号使用（函数体里若调用了特定型号的积木，需要自己确认兼容）。

## 6. 卸载清单（想彻底不留痕迹）

1. `还原原版.cmd`（UAC 点「是」）→ 资源包回到原版；
2. 关闭 IDE，确认能正常打开；
3. 删除 `WER_函数库` 文件夹（含备份）。可选：先保留备份 1 份以备将来重装；
4. 不涉及注册表、不改项目文件、不改 AppData 项目列表（安装/还原都不动用户数据）。

> 如果之前用过旧方案（框架/便携版/项目列表安装等），本方案不负责清理它们；旧目录仅存档，见 README §9「历史」。

## 7. 常见故障与恢复

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `restore` 报「没有找到原始资源包备份」 | 备份被删/移动 | 见 §2.5；或用 `--from-backup` 指定 |
| `restore` 报「备份 hash 与本机记录不一致」 | 备份来自其它版本/其它机器 | 确认版本后加 `--force`；否则换正确备份 |
| `install` 报「源资源包已打过补丁」 | 工具用错了基准包 | 用备份原版作为 `--source-assets`，或先 `restore` |
| `install` 报「找不到资源包」 | 安装路径不同/软件未装 | 用 `--assets` 指定；确认路径下确有 `browser_assets` |
| 安装中途断电/关闭窗口 | 替换是原子的，真实文件要么旧要么新 | 重新跑一次 `install` 即可（会自动处理补丁版/原版两种状态） |
| IDE 启动白屏/异常，想立刻恢复 | — | 关 IDE → `还原原版.cmd` → 重开 IDE；仍异常则重启电脑/重装软件 |
| 真实 `browser_assets` 被其它软件改坏（sha 不明） | 重装/其它补丁工具 | 用 `status` 确认是否「未识别」；用备份还原或重装软件 |
| 装完两个补丁叠加（旧方案残留） | 旧模板注入方案未清理 | 还原原版后，按本方案重装；旧方案文件别再用 |

### 7.1 磁盘空间与目录占用

- 备份 1 份 ≈ 81 MB（资源包原大小）；
- 构建临时目录在 `_分析临时\native_work\`（工作区没有被拷贝到目标机时，用系统临时目录），构建结束自动清理；
- 安装时真实资源包会变成 ≈ 81 MB + 几十 KB。

### 7.2 安全软件 / 还原卡 / 影子系统

- 杀毒软件可能拦截「替换 Program Files 文件」或「启动无头浏览器」：把 `WER_函数库` 加入信任，或临时关闭；
- 装了**还原卡/影子系统**的电脑：重启后安装会消失（属于环境行为，不是补丁问题），需在保护模式下安装或联系机房管理员。

## 8. 风险与免责（务必了解）

1. 本工具通过修改官方安装目录下的资源包实现功能，**不属于官方支持的功能**；官方升级可能改变页面结构导致补丁失效，需重打或更新工具。
2. 安装/还原需要管理员权限；请只在**自己管理的电脑**上操作，重要电脑先做系统备份。
3. 原生块与函数名绑定：改名会让旧工程旧块失效；用原生块保存的工程在未打补丁的电脑上会缺块。
4. 工具会校验资源包 sha/条目并自动备份，但仍建议每次操作后按 [操作记录模板.md](操作记录模板.md) 留档（含操作前后 sha256）。
5. 只在开发机验证过 1.0.3.4；其它版本会警告但不保证完全兼容，请先 `status` 核对 sha 并做好备份。
