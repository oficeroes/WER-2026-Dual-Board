## 二、`while not` 的括号/优先级核对（Lead 重点问的）

### 2.1 块视觉与生成器的对应关系（真实源码）

- 块定义 `blocks/myrobotrun.js` L869-884：`while_cmp` 的显示文案是
  `Blockly.Msg["ABILIX_SCRATCH_CATEGORY_REPEAT_UNTIL"]`，即 **“重复执行直到”**
  （msg 定义：`msg/js/zh-hans.js` 中 `ABILIX_SCRATCH_CATEGORY_REPEAT_UNTIL = "重复执行直到"`）。
- 生成器 `generators/myrobotpythoncode.js` L621-629：
  `var code = 'while not ' + value_bool + ':\n' + statements_code + '';`
  → “重复执行直到 <条件>”翻译成 `while not <条件>`，**方向正确**。

### 2.2 Python 运算符优先级核对（用 CPython AST 实测）

当前函数库里 8 处 `while_cmp`：

| 函数 | 生成源码行 | AST 实际解析 | 与“重复执行直到”一致 |
|---|---|---|---|
| func_ForwardCM | L92 `while not robot.abs(robot.get_encoder(1)) >= (cm * var_1cm):` | `not (abs(...) >= (cm*var_1cm))` | ✅ |
| func_BackwardCM | L110 同上 | 同上 | ✅ |
| func_TurnLeft | L128 `while not robot.abs(robot.get_encoder(1)) >= (deg * var_1angle):` | `not (... >= ...)` | ✅ |
| func_TurnRight | L145 同上 | 同上 | ✅ |
| func_LineTime | L239 `while not robot.get_timer_ms(2) >= (sec * 1000):` | `not (... >= ...)` | ✅ |
| func_LineUntilCross | L257 `while not robot.get_gray(7) >= var_ray_white:` | `not (... >= ...)` | ✅ |
| func_WaitStartKey | L271 `while not robot.check_key(1) == 1:` | `not (check_key(1) == 1)` | ✅ |
| func_WaitTouch | L279 `while not robot.get_touch(1) == 1:` | `not (get_touch(1) == 1)` | ✅ |

实测（CPython 3.12 `ast.parse`）：
```
not x >= y                    -> UnaryOp(Not, Compare(x, GtE, y))       # = not (x >= y)
not robot.check_key(1) == 1   -> UnaryOp(Not, Compare(Call(...), Eq, 1))
```
Python 中比较运算符优先级高于 `not`，所以 `not a >= b` 恒等于 `not (a >= b)`，
当前库所有“重复执行直到”都安全，**不补括号也不会改变语义**。

### 2.3 但有一个“未来函数”风险必须记住（重要）

本 IDE 的 Blockly 生成器**把 `valueToCode` 的自动括号补全注释掉了**：
`core/generator.js` L243-274，其中 L272 是 `// code = '(' + code + ')';`（整句被注释）。
因此表达式括号完全依赖各块生成器自己加：

- `math_op` 自己加括号：`generators/myrobotpythoncode.js` L1064 `'('+ A + op + B +')'` ✅
- 一元负号自己加：L1088-1089 `'-(` + operand + `)'` ✅
- `math_compare` 输出**裸比较式**：L1074 `value_a + ' ' + comparison_operator + ' ' + value_b`，返回 `ORDER_NONE` ⚠️
- `logic_operation`（and/or）输出裸组合：`generators/python/logic.js` L74-97 ⚠️

结论：
- 当前函数库所有比较都直接位于 `if` / “重复执行直到”的条件位置，**安全**。
- 如果以后把 **and/or 组合**放进“重复执行直到”条件，生成的 `while not a and b` 会被 Python
  解析成 `while (not a) and b`（实测：a=True,b=False 时 `not a and b`=False，而 `not (a and b)`=True，
  语义可能相反）。**这是编辑器生成器的固有坑，不是本函数库的 bug**；使用文档应避免/提醒。
- 同理，把“比较块”嵌进算术运算块（如 `(a>=b) + 1`）也会因缺括号产生优先级问题；当前库未出现。

## 四、使用要求 / 注意点 / 可疑点清单（按重要度）

1. **【使用要求｜高】拖出调用块后必须填参数**。
   参数槽为空时生成器会输出 `None`（`generators/python/procedures.js`：`valueToCode(...) || 'None'`），
   即 `func_ForwardCM(None)`、`func_Show(None)`。前者一进 while 条件就 `None * var_1cm` → 运行时 TypeError。
   → README/使用说明必须写：**拖出来后把参数槽填上“数字/文本”积木**（`--drag-test` 已实测填上后正常）。
2. **【未来风险｜高】“重复执行直到”里不要直接拼 and/or**（原因见 2.3）；
   当前函数库无此问题，但用户/扩展函数要注意。
3. **【工程注意｜中】func_LineTime / func_LineUntilCross 使用“计时器2”**（`robot.reset_timer(2)` /
   `robot.get_timer_ms(2)`）。用户程序里若别处也用计时器2 会互相清零干扰，建议文档提醒。
4. **【键码待确认｜中】func_WaitStartKey 用 `robot.check_key(1)`**；工具里该下拉框显示“Enter键”
   （`blocks/myrobotrun.js` L67-69：Enter键=1、Left键=2、Right键=3），块前缀文案是“Start按键”。
   “Start/确认键”在实机上是否映射为键码 1，需要实机按一下验证。
5. **【触摸语义待确认｜中】func_WaitTouch 用 `robot.get_touch(1) == 1`**：
   块视觉是“碰撞 端口1 碰到物体”（Boolean 输出），生成器 `robot.get_touch(1)`；
   Python 里 `True == 1` 为真，所以返回 True/False 或 1/0 都能正确判断；但哪个物理端口/是否常闭需实机确认。
6. **【实机未知｜中】robot 封装 API 存在性/行为**：`robot.abs/get_ee/check_key/print/play/get_timer_ms/
   get_touch/get_gray/...` 是官方生成器输出，headless 无法运行 libstarpy 验证；
   只能确认“生成代码与官方生成器一致、语法合法”。
7. **【算法未验证｜中】定距/转角/PID 的实际效果取决于：`var_1cm`、`var_1angle` 的标定值、
   电机方向、地面灰度白值、机械结构**；本函数库只保证“块→Python 的翻译正确”，不保证实车参数。
   换车/换场需重新标定（`func_Init` 里的 90.4 / 17.8 / 1300 等）。
8. **【无害现象｜低】参数名同时是工程变量**：生成文件顶部会出现 `cm = None`、`deg = None`…
   以及 main/其他函数的 `global cm, …` 列表（这是 IDE 生成器把“参数变量”当普通变量的既有行为，
   与官方 PI.py 风格一致），不影响执行：函数内参数是局部变量、且被正确排除在该函数的 `global` 之外
   （`--param-test` 已断言 `global` 里不含 `cm`）。
9. **【无害现象｜低】`robot.reset_encoder(1);` 行尾分号**：官方生成器原样输出，Python 合法。
10. **【无问题｜已核对】** `if var_ready == 1:`（生成器不补括号但 `==` 优先级低于 `if` 语句，语义正确）、
    `math_op` 自带括号、一元负号 `-(...)` 自带括号、`set_motor` 速度 clamp(-100,100)、
    `motor_time` / `set_double_motor_time` 时间 clamp(0,3600) 等均与块视觉一致。
