# run_validate.py 验证方法（headless 真机引擎验证）

> 目的：在不启动 IDE、不修改安装目录的前提下，用**软件自带的真实 Blockly 引擎 + 真实 Python 生成器**
> 验证一个 WER/AbilixScratch3.0 项目文件（`.srh` / `.srhs` / 项目 XML）：
> 能否加载、函数分类里能否看到/拖出函数调用块、生成的 Python 是否正确、语法是否合法、渲染是否正常。
>
> 工具：`WER_函数库/工具/验证/run_validate.py`（单文件，Python 3.8+；本机用捆绑 Python 3.12）
> 依赖：软件解包目录 `_分析临时/blockly_web`（含真实 `Blockly_Code` 与 `closure-library`）、本机 Chrome/Edge。
> 本工具只读这些目录，**不修改** `_分析临时/`、安装目录、用户项目。

## 1. 怎么跑

```bat
:: 最常用：验证一个项目（.srh / .srhs / 项目 XML 均可）
python run_validate.py 项目.srh

:: 输出 JSON + 生成的完整 Python
python run_validate.py 项目.srh --json out\result.json --py out\generated.py

:: 黄金样本对比：与官方生成结果做结构化对比（26 个函数 + main）
python run_validate.py _分析临时\PI\abilixProject.srh ^
  --compare-ref 逆向资料\样本程序\PI.py --program-name ProgramA --diff-out out\PI.diff

:: 带参数函数最小用例（内置 XML：def 带 mutation arg + 函数体 variables_get 参数 + main 调用带 ARG0 值）
python run_validate.py --param-test

:: 拖拽可用性：从“函数”分类把每个调用块用真实 Flyout.createBlock 拖出来，接入 start 再生成
python run_validate.py WER_函数库\示例\WER函数库.srhs --drag-test

:: 原生函数积木：真实选中“我的函数”分类 → 实例化 flyout → 逐个 createBlock 拖出 → 接入 start → 生成
:: （要求 --web-root 指向已打原生函数积木补丁的 web 根，例如 _分析临时\native_work\patched_web；
::  补丁由 WER_函数库\工具\底层\patch_browser_assets.py 对解包资源生成）
python run_validate.py _分析临时\native_work\evidence\native_test.srh --native-test ^
  --web-root _分析临时\native_work\patched_web --screenshot --window-size 1600,1800

:: 语义核对：逐函数输出「块结构 vs 生成 Python」Markdown + 自动括号/优先级风险扫描
python run_validate.py WER_函数库\示例\WER函数库.srhs --semantic-out out\语义核对.md

:: 截图：额外跑一次 Chrome，自动选中“函数”分类并截图（窗口高度足够大才能拍全函数列表）
python run_validate.py WER_函数库\示例\WER函数库.srhs --screenshot out\flyout.png --window-size 1600,2000

:: 一次把证据都留档（JSON/报告/生成 py 写进目录）
python run_validate.py 项目.srh --evidence-dir 证据\某次验证 --screenshot
```

> Python：用 PATH 里的 `python` / `py -3` 即可（要求 3.8+，只用标准库）。
> 若 PATH 里没有，用 `where python` 找到你的 Python 路径后替换上面命令里的 `python`。
> Chrome 默认自动找 `C:\Program Files\Google\Chrome\Application\chrome.exe`（可用 `--chrome` 指定 Edge 等）。

### 参数速查

| 参数 | 说明 |
|---|---|
| `input` | 项目文件 `.srh` / `.srhs` / 项目 XML；`--param-test` 时可省略 |
| `--json PATH` | 完整结果 JSON（含生成代码、flyout 列表、渲染统计、断言明细） |
| `--py PATH` | 生成的完整 Python（UTF-8 + LF，按 PC → 机器人下载文件风格） |
| `--compare-ref PATH` | 与参考 Python 结构化对比：函数名/参数/函数体 token/diff/一致率 |
| `--diff-out PATH` | 归一化 unified diff 输出 |
| `--fail-on-diff` | 对比存在“非允许差异”时返回失败（适合作为 Lead 的 CI 式检查） |
| `--param-test` | 内置“带参数函数”最小用例（16 项断言） |
| `--drag-test` | 函数分类 flyout → `createBlock` 拖出全部调用块 → 接入 start → 生成（13 项断言） |
| `--native-test` | 「我的函数」分类 flyout → `createBlock` 拖出全部原生函数块（含参数）→ 接入 start → 生成（32 项断言；要求 `--web-root` 含 `Blockly_Code/abilix_userlib.js`） |
| `--semantic-out PATH` | 逐函数「块结构 vs 生成 Python」核对 Markdown + 自动风险扫描 |
| `--screenshot [PATH]` | 额外截图；不带路径时写 `--evidence-dir` 或工具 `证据/` 目录 |
| `--window-size W,H` | Chrome 窗口尺寸，默认 `1600,1000`；函数多时用 `1600,2000` |
| `--evidence-dir DIR` | 把 `<时间戳>_<文件名>.json/.report.txt/.py` 写进目录 |
| `--chrome PATH` | 指定 Chrome/Edge（也可用环境变量 `CHROME_PATH`） |
| `--web-root DIR` | 指定 `blockly_web` 目录（默认 `_分析临时/blockly_web`） |
| `--work-dir DIR` | 临时目录父目录（默认系统 temp，运行结束自动清理） |
| `--robot-type` / `--connection-type` / `--program-name` | 覆盖项目 Info 里的值（`--program-name` 会影响生成文件头 `#<...>`） |
| `--timeout 秒` | 单次 Chrome 超时，默认 240 |
| `--keep` | 保留临时目录以便调试 |

退出码：`0` 通过；`2` 验证/断言失败；`3` harness 运行失败（工具/环境问题）。
运行结束会打印中文文本报告；`--evidence-dir` 会额外落盘 JSON/报告/生成 Python。

## 2. 原理（为什么是“真实引擎验证”）

```
run_validate.py
 ├─ 1. 读项目：.srhs=zip(唯一条目 abilixProject.srh，zip 注释=机器人枚举 111/110/112)
 │             .srh=按 <Abilix.ScratchProject.Info>/<ProjectString> 标记截取
 │             → 得到 ProjectString XML + RobotType + DownloadProgramName
 ├─ 2. 起本地 http.server（127.0.0.1 随机端口，只读，服务 _分析临时/blockly_web 根目录）
 │     · /Blockly_Code/__harness__.html      ← 动态生成的 harness 页面
 │     · /Blockly_Code/blocks/procedures.js  ← 唯一 GBK 文件，响应时 GBK→UTF-8 转码（代码内容一字不改）
 │     · /__api__/result                     ← harness 把结果 JSON POST 回来
 ├─ 3. Chrome --headless=new 打开 harness 页面
 │     · 按 maingui.html 的真实 script 顺序加载：blockly_uncompressed.js（真 Blockly 核心）、
 │       generators/python*.js（真 Python 生成器）、blocks/*.js（真积木定义）、
 │       maingui_init.js（加载 msg/js/zh-hans.js）、blocks/myrobotrun.js、
 │       generators/myrobotpythoncode.js（真机器人生成器）、project_config.js
 │     · 工具箱直接用 maingui.html 里原样抠出的 <xml id="toolbox_skcon9">（真工具箱数据，非重写）
 │     · Blockly.inject → 真实 WorkspaceSvg；Blockly.Xml.domToWorkspace 加载项目
 │     · Blockly.Procedures.flyoutCategory(workspace) 得到“函数”分类真实 XML 清单
 │     · 通过 Toolbox 树真实选中“函数”分类 → flyout_.show() → 实例化出真实 flyout 块
 │     · 可选 --drag-test：对每个 flyout 调用块调用 Flyout.createBlock（IDE 拖拽落地的同一个函数），
 │       填参数、接到 start 的 code 语句链末尾
 │     · 可选 --native-test：遍历真实工具箱树找到“我的函数”分类（由 abilix_userlib.js 注册的 abilixuf_* 原生块），
 │       ToolboxTree.setSelectedItem 真实选中 → flyout_.show() 真实实例化 → 对每个原生块调用 Flyout.createBlock
 │       拖出、给参数槽填 math_number、逐个接到 start 的 code 链，再用真实 maingui.getPythonCode 生成
 │     · 原生块 prelude 回归：统计工程 XML 里的原生块数量，核对生成代码是否按需注入 abilixUserLibPython
 │     · 生成 Python：直接 eval maingui.js 里抠出的原始 getPythonCode 源码
 │       （文件头 #<机器人><连接><程序名> + import + robot = Robot() + workspaceToCode + main()）
 │     · 结果 JSON 同步 XHR POST 回本地服务器；同时清空大 DOM，让 --dump-dom 输出很小
 ├─ 4. Python 侧复核：分析生成代码结构、py_compile 语法检查、与 PI.py 结构化对比、
 │    带参数函数断言、拖拽断言、语义风险扫描
 └─ 5. 可选第二次 Chrome --screenshot：同一 harness 页面 ?shot=1，选中“函数”分类后截图
```

要点：
- **不是重写生成器**：所有块定义、生成器、工具箱、`getPythonCode` 都来自软件解包出的真实 Web 资源；
- **不启动 IDE 主界面**：不加载 CodeMirror/layui/maingui.js 这些纯 UI 依赖，避免 CEF 依赖；
- **真实渲染**：`Blockly.inject` 创建的是真实 `Blockly.WorkspaceSvg`，所有块都真正渲染成 SVG，
  报告中给出“已渲染块数/SVG 根数量/0 尺寸块数/块警告数/console 错误”等健康度数据；
- **截图可肉眼复核**：能看到左侧“函数”分类高亮、flyout 里的函数调用块（含参数槽）、工作区里的函数定义块。
- **原生块真实链路**：`--native-test` 不构造 XML，而是“真实工具箱树选中分类 → flyout 真实实例化 →
  `Flyout.createBlock` 拖出 → 真实 `getPythonCode` 生成”，并逐项核对注入的 `def`、`main` 调用与 `py_compile`。
  截图会额外产出分步证据图（page/flyout/drag/python），右侧直接贴出真实生成的 Python 全文。

## 3. 输出怎么读

文本报告分段：
`[1] 加载项目 XML`（是否成功、耗时、顶层块/总块/变量数、渲染健康度）
`[2] 函数定义`（`procedures_defnoreturn` 列表：函数名 + 参数）
`[3] 函数分类 flyout（Blockly.Procedures.flyoutCategory）`（每个 XML 块的 type/name/args）
`[4] 真实 flyout 实例化`（真实 flyout 里实例化出的块 type/name/args/inputs，渲染统计）
`[5] Python 生成`（是否成功、是否用了 maingui.js 原始 getPythonCode、行数、文件头、import、变量声明、尾部）
`[6] py_compile`（语法检查是否通过，失败时给 stderr）
`[7] 与参考对比`（`--compare-ref` 时：函数数/一致率/参数签名/函数体/变量声明/允许差异/diff 行数）
`[8] 带参数函数结论`（`--param-test` 时 16 项断言明细）
`[9] 拖拽可用性`（`--drag-test` 时 13 项断言明细）
`[10] 原生函数块`（`--native-test` 时 32 项断言明细：分类选中/flyout 实例化/拖出/参数填值/接入 start/文件头/import/prelude/def/main 调用/py_compile）
`[11] 原生块 prelude 注入回归`（工程含原生块时注入、不含时不注入；`--web-root` 无 `abilix_userlib.js` 时显示「跳过」）
末尾：注意（window/console 错误、超时等）+ 结论。

JSON 主要字段：`meta / project / chrome / harness / analysis / syntaxCheck / comparison / paramTest / dragTest / nativeTest / nativePrelude / userlib / nativeBlocks / screenshot / screenshots / errors / ok`。
其中 `harness` 就是浏览器里算出来的原始结果：`load / workspace（含 render）/ procedures / flyout.categoryXml / flyout.instantiate / native / generation / drag / steps / windowErrors / consoleErrors`。
`--native-test` 且 `--screenshot` 时 `screenshots` 是 4 条分步截图记录（kind=page/flyout/drag/python），`screenshot` 仍保留主截图旧字段。

## 4. 已知限制与注意事项

1. **只保证“生成结果正确”，不保证实机运行**：headless 无法运行 `libstarpy`，`py_compile` 只查语法；
   电机方向、传感器读数、标定参数需实车验证。
2. **浏览器资源版本锁定**：验证结果对应 `_分析临时/blockly_web` 这一份解包资源（即本机 IDE 的资源）。
   如果 IDE 升级导致资源变化，需要重新解包，工具会自动使用新资源（无需改代码）。
3. **GBK 文件**：`Blockly_Code/blocks/procedures.js` 是 GBK，服务器在响应时转 UTF-8（内容不变）。
   其它 Web 资源本机实测均为 UTF-8。若换机器发现其它 GBK 文件，浏览器会按 UTF-8 解码，
   注释里的中文可能变乱码但不影响生成逻辑（字符串字面量中的中文才会受影响，届时可扩展转码列表）。
4. **`.srhs` 的 zip 注释**用于推断机器人类型（112=SKCON2、110=SKCON5、111=SKCON9）；
   如果 Info 段里也有 `<RobotType>` 则以 Info 为准。
5. **连接方式/程序名**：`.srh` 的 Info 里通常没有 ConnectionType，默认按 `USB`；
   程序名取 `DownloadProgramName`，它只影响生成文件头 `#<SKCON9><USB><程序名>`。
   与官方样本对比时如果程序名不同，用 `--program-name` 对齐。
6. **截图**：`--screenshot` 会额外启动一次 Chrome（页面 `?shot=1` 会自动选中“函数”分类）。
   想拍全 20 个函数，用 `--window-size 1600,2000`（窗口太矮只会拍到前几个）。
7. **无头环境**：需要能执行 Chrome；若企业策略限制，可 `--chrome`/`CHROME_PATH` 指向 Edge。
   运行中会创建临时 Chrome profile（在系统 temp，结束后自动删除，不污染用户 Chrome 配置）。
8. **性能**：PI 级项目（1945 块）约 2.8s 完成数据验证，加截图约 7s；普通项目 1-4s。
9. **`--compare-ref` 的“允许差异”**：目前只把“文件头程序名不同”“变量声明集合相同但顺序不同”列为允许差异；
   其余任何差异都会出现在报告和 diff 里（可用 `--fail-on-diff` 强制失败）。
10. **`--native-test` 的前提与限制**：
    - `--web-root` 必须是已打「原生函数积木」补丁的资源根（含 `Blockly_Code/abilix_userlib.js`，
      如 `_分析临时/native_work/patched_web`）；普通 web 根会直接退出码 2 并提示，不启动 Chrome。
    - 被测项目需含 `start` 块（拖出的原生块要接到 `start` 的 code 语句链），否则断言失败。
    - 原生块参数槽统一填 `math_number`，数值按 `10*(flyout 序号+1)+参数序号` 合成（含 text 类型参数槽），
      用于确定性验证「连线 → 生成」链路；不校验参数语义类型。
    - 拖拽前会移除工作区里工程自带的 `abilixuf_*` 原生块（`removedCount` 记入 JSON），保证生成内容全部来自本次真实拖出。
    - harness 只加载 Blockly 核心样式，flyout 背景可能是透明的，但块列表、渲染与生成逻辑均为真实引擎结果。
    - `--screenshot` 在 native 模式会额外产出 4 张分步截图（page/flyout/drag/python），建议 `--window-size 1600,1800`。

## 7. 运行环境资源（重要）

本工具需要一份**解包后的软件 Web 资源**目录（`blockly_web`：包含 `Blockly_Code/` 与 `closure-library/`），
默认路径是 `_分析临时\blockly_web`。项目交付时为保持目录精简，`_分析临时` 里的大文件已清理；
如果该目录不存在，先重新解包（几秒，不需要管理员权限）：

```bat
python 逆向资料\unpack_zfb.py
:: 默认解包到 逆向资料\blockly_web（脚本里 out 路径写死）
python WER_函数库\工具\验证\run_validate.py 项目.srh --web-root 逆向资料\blockly_web
```

另外 `--chrome` 默认找本机 Chrome；没有 Chrome 时可显式指定 Edge：
`--chrome "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"`。
