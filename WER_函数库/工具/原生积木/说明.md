# 原生积木核心工具 · 说明

> 工具：`WER_函数库/工具/原生积木/原生积木核心.py`（v1.0.0）
> 作用：把 `我的函数库.srhs` 编译成 AbilixScratch3.0 **内部的原生积木**（左侧「我的函数」分类 + 右侧 Python 自动带函数定义）。
> 普通用户不用看本文件：直接双击 `安装原生积木.cmd` / `状态检查.cmd` / `还原原版.cmd` 即可（见 [../../README_从这里开始.md](../../README_从这里开始.md)）。
> 本文给：想用命令行、排错、二次开发或在多台电脑上批量操作的人。

| 项 | 要求 |
| --- | --- |

## 4. 子命令总览

| 子命令 | 作用 | 碰真实安装目录？ | 需要管理员？ |
| --- | --- | --- | --- |
| `build` | 编译函数库 → 输出打过补丁的资源包（`.bin`），可选解包 web 目录 | 否 | 否 |
| `install` | 备份原版 → 编译 → 原子替换真实 `browser_assets` | **是** | **是** |
| `restore` | 用备份恢复原版资源包 | **是** | **是** |
| `status` | 只读检查：补丁状态/函数库是否变化/备份/IDE 是否运行 | 否 | 否 |
| `verify` | 校验一个补丁包相对原始包是否正确（2 改 + 2 增 + 其余逐字节不变） | 否 | 否 |
| `extract-web` | 解包 `browser_assets` 到目录（查看/对照/给验证工具用） | 否 | 否 |

退出码：**0** 成功；**1** `status` 有错误 / `verify` 失败；**2** 参数错误或运行失败（打印 `✘ 失败：…`）。

## 5. `build`：只编译，不安装

```
python 原生积木核心.py build --library <函数库.srhs|.srh> --source-assets <原始 browser_assets> --out <输出.bin> [选项]
```

| 参数 | 必填 | 默认 / 说明 |
| --- | --- | --- |
| `--library` | 否 | `WER_函数库\我的函数库.srhs` |
| `--source-assets` | **是** | 原始资源包路径（未打补丁的 `browser_assets`） |
| `--out` | **是** | 输出补丁包路径（不能与 `--source-assets` 相同） |
| `--workdir` | 否 | 临时工作目录（默认 `<WER_函数库 的上一级>\_分析临时\native_work\build`；系统临时目录可用） |
| `--keep-work` | 否 | 保留临时目录（调试用） |
| `--prelude-out` | 否 | 把生成的函数定义 prelude 另存为文件 |
| `--prelude-in` | 否 | 用现成 prelude 文件（跳过浏览器引擎，适合无 Chrome 的机器二次构建；会校验每个函数 def 都在） |
| `--web-out` | 否 | 把补丁包解包到目录（给 `run_validate.py --web-root` 用） |
| `--json-out` | 否 | 结果写入 JSON |
| `--timeout` | 否 | 真实引擎生成超时秒数（默认 300） |

示例：

```bat
python WER_函数库\工具\原生积木\原生积木核心.py build ^
  --library WER_函数库\我的函数库.srhs ^
  --source-assets "D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets" ^
  --out _分析临时\browser_assets_patched.bin ^
  --web-out _分析临时\native_work\patched_web
```

成功输出末段：

```
完成：_分析临时\browser_assets_patched.bin
  大小 81.3 MB（原始 81.3 MB，增加 3.9 KB）
  sha256 …
  函数 1 个；prelude 61 字符
  用时 44.3 秒
```

自检规则（不通过则 build 失败）：原条目顺序不变、只允许 `maingui.html`/`maingui.js` 变化、恰好新增 `abilix_userlib.js` + `abilix_userlib.json`、其余逐字节不变。

## 6. `install`：安装到本机 IDE

```
python 原生积木核心.py install [--assets ...] [--library ...] [--backup-dir ...] [选项]
```

| 参数 | 默认 / 说明 |
| --- | --- |
| `--assets` | `D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets` |
| `--library` | `WER_函数库\我的函数库.srhs` |
| `--backup-dir` | `WER_函数库\工具\原生积木\备份` |
| `--source-assets` | 当前已是补丁版时，用来重新编译的**原始**资源包；默认自动找备份 |
| `--workdir` | 构建临时目录 |
| `--prelude-in` | 用现成 prelude（跳过浏览器引擎） |
| `--force` | IDE 运行时也继续（不建议） |
| `--dry-run` | **演练**：在系统临时目录的副本上走完整流程，不碰真实安装目录 |
| `--compile-only <输出补丁包>` | **只编译、不安装**：普通权限即可跑（浏览器引擎可用），生成打过补丁的 `.bin` 后退出。两段式安装的第 1 段。 |
| `--prebuilt <补丁包>` | **跳过浏览器引擎**，把已编译补丁包直接安装到目标：校验来源 sha 一致 → 备份 → 原子替换 → 回读校验。需管理员，两段式安装的第 2 段。 |
| `--json-out` / `--json` | 结果写 JSON 文件 / 打印 JSON |

行为顺序：

1. 检查管理员（非管理员直接报错并提示用 `.cmd`）；
2. 检查 IDE 是否运行；
3. 检查资源包存在；
4. 若当前**未打补丁**：先备份原始资源包（`备份\browser_assets.原始.<sha12>.bin`）；
   若**已打补丁**：找已有备份（或 `--source-assets`）作为基准**重新编译**；
5. 编译到临时文件 → 原子替换真实资源包 → 回读 sha256/manifest 校验；
6. 打印「安装完成 ✔」+ 函数列表 + 还原方法。

> **为什么需要两段式**：管理员提权进程里 Chrome/Edge 的无头模式会失效（实测 Chrome 157：启动 80ms 即退出、无 DOM），所以 `安装原生积木.cmd` 先在**普通权限**下 `--compile-only` 编译，再自提升只跑 `--prebuilt` 做替换。手动排错时也可以照这个顺序跑。

常用：

```bat
:: 演练（推荐在陌生电脑先跑一次）
python WER_函数库\工具\原生积木\原生积木核心.py install --dry-run

:: 非默认安装路径
python WER_函数库\工具\原生积木\原生积木核心.py install ^
  --assets "E:\App\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets"

:: 无 Chrome/Edge 的机器：用另一台机器生成好的 prelude 编译
python WER_函数库\工具\原生积木\原生积木核心.py install --prelude-in _分析临时\prelude.py
```

## 7. `restore`：还原原版

```
python 原生积木核心.py restore [--assets ...] [--backup-dir ...] [--from-backup <备份文件>] [--force] [--dry-run]
```

- 默认从 `--backup-dir` 找备份，**优先**选「本机记录的原版 sha256」匹配的那份，否则取最新一份；
- 备份 sha 与本机记录的原版 sha 不一致时拒绝，确认无误加 `--force`；
- 成功输出「还原完成 ✔」+ sha256 + 是否与本机记录原版一致；
- 找不到备份会报错并给出备份目录位置，可用 `--from-backup` 指定或先重装软件。

```bat
:: 演练
python WER_函数库\工具\原生积木\原生积木核心.py restore --dry-run

:: 指定备份 / 新版软件降级回“新原版”
python WER_函数库\工具\原生积木\原生积木核心.py restore --from-backup "工具\原生积木\备份\browser_assets.原始.df6db241752d.bin"
python WER_函数库\工具\原生积木\原生积木核心.py restore --from-backup "工具\原生积木\备份\browser_assets.原始.<新sha12>.bin" --force
```

> 升级软件后不要直接用旧备份还原（会把旧版本资源包装到新软件上），详见 [../../修改软件说明/04_回滚与升级重打.md](../../修改软件说明/04_回滚与升级重打.md) §4.2。

## 8. `status`：只读检查

```
python 原生积木核心.py status [--assets ...] [--library ...] [--backup-dir ...] [--json-out ...] [--json]
```

输出（人类可读）字段：

- 资源包路径 / 大小 / sha256；
- 管理员：是/否；
- IDE 运行：是/否；
- 原生积木：`未打补丁（原版资源包）` / `已打补丁 v1.0.0 <builtAt>` / `未识别（不是原版，也没有本工具清单）`；
- 补丁时函数库 / 补丁时函数 / 当前函数库 / 是否需要重装（`是（函数库有变化）` 或 `否（已同步）`）；
- 函数变化：原来 … / 现在 …；
- 备份 N 份（列出前 5 个路径/大小/hash 前 16）；
- 「建议：」段落（下一步该做什么）。

`--json` 字段：`assets, library, backupDir, assetsExists, admin, ideRunning, patched, needSync, recommend, errors, assetsSize, assetsSha256, original, backups, manifest, patchedLibrary{sha256,defs}, builtAt, libraryExists, librarySha256, defsDiff{old,current,same}`（出错时 `defsDiff.error`）。

`needSync=true` 的含义：当前 `我的函数库.srhs` 的 sha256 ≠ 清单记录，或函数名列表变了 → 需要重新 `install`。

## 9. `verify` / `extract-web`

```bat
:: 校验补丁包（2 改 + 2 增 + 其余逐字节不变）
python 工具\原生积木\原生积木核心.py verify ^
  --file _分析临时\browser_assets_patched.bin ^
  --original "D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets"

:: 解包资源包（查看/对照/给 run_validate.py 用）
python 工具\原生积木\原生积木核心.py extract-web ^
  --assets "D:\Program Files\AbilixScratch3.0\AbilixScratch3.0_Data\Resources\browser_assets" ^
  --out _分析临时\web_unpacked
```

`verify` 成功输出「校验结果：通过 ✔」+ 修改/新增条目 + 「其余 N 个条目逐字节不变」；失败输出「失败 ✘」+ 错误清单，退出码 1。
`extract-web` 输出「解包资源包：… -> …」「完成：N 个条目」。

## 10. 备份与安全设计

- **备份**：`备份\browser_assets.原始.<原包 sha256 前 12 位>.bin`；幂等（已存在不覆盖），复制后校验 sha，失败报「备份校验失败」。
- **原子替换**：先写同目录临时文件 `.browser_assets.new.<pid>.tmp` + fsync，再 `os.replace`；中途失败真实文件不变。
- **IDE 保护**：`tasklist` 检测 `abilixscratch*` 进程，运行中默认拒绝安装/还原。
- **权限**：非管理员直接报错并提示「右键『安装原生积木.cmd』→ 以管理员身份运行」。
- **状态清单**：安装后写/读 `abilix_userlib.json`（补丁清单），`status` 靠它判断「是否需要重装」。
- **不做的事**：不改 `.srh/.srhs` 工程文件、不改 AppData 项目列表、不写注册表。

## 11. 常见错误信息与处理

| 输出/错误 | 处理 |
| --- | --- |
| `需要管理员权限。请右键「安装原生积木.cmd」…` | 用 `.cmd` 双击并点 UAC「是」；或管理员命令行运行。 |
| `IDE 正在运行（…）。请先关闭 AbilixScratch3.0 再操作` | 关闭 IDE（任务管理器确认）；确认要冒险可 `--force`。 |
| `找不到资源包：…` | 安装路径不同：`--assets` 指定；或软件没装。 |
| `函数库里没有函数定义（procedures_defnoreturn）…` | 打开 `我的函数库.srhs` 确认至少有一个「新建函数」定义。 |
| `函数名 %r 不是合法的 Python 标识符…` | 回 IDE 改成英文/数字/下划线且非数字开头，保存后重装。 |
| `函数库里有重名函数` / `积木类型上冲突` | 改掉重复函数名。 |
| `这个资源包已经是打过原生积木补丁的版本…` | 用原始备份作 `--source-assets`，或先 `restore` 再 `install`。 |
| `输出路径不能与原始资源包相同` | `--out` 换个路径（不要覆盖原版）。 |
| `真实引擎生成函数库 Python 失败（退出码 …）` | 需要有 Chrome 或 Edge；排除浏览器策略/杀软；可改用 `--prelude-in`。 |
| `真实引擎生成函数库 Python 失败（退出码 3）` 或 `harness 未返回有效结果`，且发生在**管理员窗口**里 | 提权进程里浏览器无头模式失效（Chrome 157 实测）。用新版 `安装原生积木.cmd`（普通权限编译 → UAC 安装，两段式）重试；或手动 `install --compile-only` 后再管理员 `install --prebuilt`。 |
| `当前资源包已打过补丁，却找不到原始包备份` | 用 `--source-assets` 指定原始资源包，或 `restore` 后再装。 |
| `没有找到原始资源包备份` | 备份被删/移动；`--from-backup` 指定，或重装软件恢复原版。 |
| `这份备份的 hash 与本机记录的原始资源包不一致` | 确认版本后加 `--force`；否则换正确备份。 |
| `补丁包自检失败` / `预期给 3 个机器人工具箱加分类，实际找到 %d 个` | 源资源包不是本机 1.0.3.4（页面结构变了）。先 `extract-web` 核对；需要更新工具。 |
| `✘ 失败：…` | 清理问题后重试；退出码 2。 |

## 12. 开发说明（改代码/扩展）

- 代码结构（1210 行）：常量/路径 → 函数库解析（`load_library`）→ prelude（`build_prelude`/`extract_prelude`）→ JS/分类/补丁（`build_userlib_js`/`build_category_xml`/`patch_html`/`patch_js`）→ zfb 打包与校验（`_pack_zfb`/`verify_package`）→ 备份/安装/还原/状态（`backup_original`/`install`/`restore`/`status`）。
- 硬校验锚点：脚本锚点 `<script src="generators\myrobotpythoncode.js"></script>` 恰好 1 处；`toolbox_skcon\d` 恰好 3 个；`\t\tBlockly.Python.workspaceToCode(workspace) +` 恰好 2 处；补丁后 `abilixUserLibPython` 出现 4 次。
- 函数定义 prelude 由真实引擎生成（`工具/验证/run_validate.py`），不要手工维护第二套生成规则。
- 详细格式/字段/实现约定见 [../../修改软件说明/03_格式与实现细节.md](../../修改软件说明/03_格式与实现细节.md)。
- 自测：`python -m py_compile 原生积木核心.py`；`build` + `verify`；`install --dry-run`；`status --json`。
