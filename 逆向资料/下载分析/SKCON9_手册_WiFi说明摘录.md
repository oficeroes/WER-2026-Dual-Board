**解读**：

- ⚠️ 代码旁证：`WifiManager.IsConnectAbilixWifiPrefix()` 会检查当前 PC WiFi 的 SSID 是否以 `Abilix` 开头（`Assembly-CSharp.decompiled.cs:100192-100196`），用于 Chart 3.0 的自动扫描路径；这意味着官方 UI 预期热点名以 `Abilix` 开头。**如果用户把机器人名称改得不再以 `Abilix` 开头，Chart 路径的自动发现可能失效**（Python 路径是手动填 IP，不受影响）。手册未写这一点，属代码推断。

**解读（逐条对照软件代码）**：

| 手册步骤 | 含义 | 软件代码对应 |
|---|---|---|
| 第一步「同一局域网」 | WLAN 模式（同路由器）或热点模式（PC 连机器人热点） | `WifiConnectController.OnConnectHandler` 检查 `internetReachability == ReachableViaLocalAreaNetwork`，不通则提示「请连接同一 WiFi」（`C#:120639-120666`） |
| 第二步「选择无线连接」 | 工具栏联机方式切 WiFi | `onBtnWifi_Click` → `OnConnectionTypeChanged(ConnectionType.WiFi)`（`C#:113217-113220`） |
| 第三步「点击下载」 | 填程序名后触发下载 | `OnClickDownloadButtonHandler` / 代码模式 `onBtnDown_Click`（`C#:114375-114390`、`113419-113431`） |
| 第四步「输入 SKCON9 网络 IP」 | 4 段 IP 输入框 | `WifiConnectView`：4 个 InputField（各 0-255），预填本机 IP 前三段（`C#:120902-120924`、`120944-120996`）；提交后 `CreateSocket`（`C#:120633-120637`） |
| 第五步「等待连接与下载」 | 连 10086 心跳 + 8890 文件并传输 | `RobotService.createSocket` 同时连两端口（`C#:99047-99052`），成功后自动开始下载（`C#:120720-120731`） |
| 第六步「完成」 | 进度条走完 + 成功提示 | `DownloadFileController.DownloadFileResultHander`（`C#:117089-117116`） |
| 备注「记住 IP」 | 下次无需再输 | `PlayerPrefs["WIFI_CONNECT_IP_KEY"]` 记住上次 IP（`C#:120484-120498`、`120683-120691`），连接窗口带出上次 IP |
| 备注「IP 地址栏断开」 | 换机器人/换网络时断开 | `WifiDisconnectView` + `WifiManager.DisconnectWifi`（`C#:120742-120755`、`100162-100168`） |

**手册没写、但软件实际要求/存在的行为**（均由代码确认，手册未提）：

1. **默认连接窗口预填什么**：上次成功连接的机器人 IP 完整 4 段；没有记录时预填**本机 PC 的 IP 前三段**，只让用户填第 4 段（`C#:120668-120681`、`120902-120924`）。
2. **机器人 IP 从哪里查**：手册没有说明。代码只会用 PC 本地 IP 预填，机器人 IP 需要用户自己知道（◐ 可能显示在机器人设置页，手册未写；建议做实验确认）。
3. **首次连接后「连接方式图标变化」**：C# 里是 `PCScratchProxy.IsWifiConnected` 驱动工具栏图标切换（代码模式 `C#:113235-113271`、积木模式 `C#:114591-114615` 的 `UpdateConnectionRelativeComponents`），与手册备注一致。
4. **Python/Scratch 3.0 的同一流程**：手册这段写在 §4.1 Chart 3.0 下，但代码里 Python（`PCScratchView`/`PCScratchCodeView`）复用了同一个 `WifiConnectController`，操作步骤相同（详见《下载链路逆向.md》§5.2）。
5. **热点模式**：手册 p17 只说怎么开热点，没有写「PC 连上热点后怎么下载」；按代码，只要 TCP 能到机器人 IP 即可，和 WLAN 模式无差别（端口 10086/8890 见《下载链路逆向.md》§3.1）。

## 3. 给 VSCode 用户的操作建议（基于手册 + 代码，标注确定性）

**组网（任选其一）**：

- **A. WLAN 模式（推荐，比赛现场常用）**：机器人「设置 → WLAN」连到 2.4G 路由器；PC 连同一路由器。✅ 手册 p17 + p6。
- **B. 热点模式**：机器人「设置 → 热点」开启；PC 在系统 WiFi 列表连机器人热点（SSID 随机器人名称）。✅ 手册 p17。

**下载（Python 程序）**：

1. 用 VSCode 扩展把程序名设为 `ProgramA`/`ProgramB`/…（ASCII，≤18 字符，与机器人端约定一致；◐ 槽位命名规则待真机确认）。
2. 确认机器人 IP：WLAN 模式一般在路由器后台/机器人网络设置里；热点模式通常是热点网段的机器人地址。⏳ 手册未写，建议第一次用官方软件连接成功后，从官方 UI 记住的 IP 读到它（`WIFI_CONNECT_IP_KEY`）。
3. 扩展里填 IP → 测试连接（心跳）→ 下载（zip 传输）。
4. 若提示超时：确认 PC/机器人同一网段（前三段相同）、机器人已开机、PC 防火墙允许 TCP 10086/8890。
5. 若提示 CRC 失败/文件已存在：换程序名重试或忽略「已存在」（官方 Python 路径把 4006 当成功）。

**常见误区（手册没写，容易踩）**：

- 以为 5GHz WiFi 也行 → 手册明确仅 2.4G（p6）。
- 以为热点名可以随便改 → 改了不影响 Python 手动 IP 路径，但可能影响官方 Chart 3.0 的自动扫描（代码按 `Abilix` 前缀判断）。
- 以为文件头 `<USB>` 表示有线 → 官方软件不管用什么方式下载都写 `<USB>`（本文 §1.6 + 逆向文档 §4.5）。
- 以为「文件已存在」一定是失败 → 官方 Python 路径当成功处理（逆向文档 §3.6）。
