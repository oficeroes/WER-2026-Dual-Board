## 安装 / 还原

1. 完全关闭 AbilixScratch3.0（任务管理器确认无 `AbilixScratch` 进程）。
2. 右键**以管理员身份运行** `install_dual.cmd`（UAC 点是）。脚本会：校验当前资源包 sha → 备份到 `WER_函数库/工具/原生积木/备份/browser_assets.双板通讯前-<时间>.bin` → 写入新包 → 校验新 sha（失败自动回滚）。
3. 打开 IDE：函数栏顶部出现「双板通讯」分类（4 个积木）。
4. 还原：右键管理员运行 `restore_dual.cmd`（优先用最近一次备份回滚）。

## 4 个积木

| 积木 | 类型 | 生成代码 | 说明 |
|---|---|---|---|
| 设置对方主板 IP `[192.168.1.103]` | 语句 | `_wl_set_ip('ip')` | 只配置，不产生动作 |
| 发送 `[值]` 到地址 `[1]` | 语句 | `_wl_send(addr, 值)` | 值可为数字/文本/变量/表达式；地址 1~128 |
| 接收地址 `[1]` 的信息 | 数字 reporter | `_wl_recv(addr)` | 没有新数据时返回上次持久值或 0 |
| 把地址 `[1]` 的信息保存到读写数据 | 语句 | `_wl_save_ee(addr)` | 立即写 EEPROM（掉电不丢） |

## 数据保存（「读写数据」EEPROM）

- 地址 1~128 与主板「读写数据」01~128 **同一套槽位**。
- 「接收」积木读到新数值时会**自动写 EEPROM**：同一地址最快 1 秒写一次、只在数值变化时写（保护擦写寿命）。
- 程序重启后、本次开机还没收到新数据时，「接收」积木会**回读 EEPROM 旧值**；从未写过的地址为 0。
- 数值范围整数 -99999~99999；文本不写入 EEPROM（仅内存中用）。
- 想立刻保存（不等节流）用「保存到读写数据」积木。
- ⚠ 地址 1/2 等槽位可能已有旧数据（实测某板 01=3600、02=400），测试建议用 11/12 等空地址。

## 生成程序里的运行时（原理）

积木生成的 Python 会在 `robot = Robot()` 之后自动插入 prelude（仅当程序含 `abilixuf_` 积木时注入，无积木项目输出与官方逐字节一致）：

1. `os.system` / `fork+pipe+execv` 现场调用机器人自带 `/system/xbin/gcc4.8.2/bin/arm-linux-androideabi-gcc`，把内嵌 C 助手编译到 App 私有目录 `/data/data/com.abilix.controller/files/wlnet_helper`（`/sdcard` 是 noexec，编译产物不能就地执行）。
2. 助手用 **UDP 8990** 收发：stdin `S <ip> <addr> <value>` → 对端 `R <addr> <value>` → stdout；`P`/`K` 心跳保活；stdin 60s 无输入自动退出；程序退出时 `atexit` 杀掉。
3. Python 侧线程读 stdout、维护「地址→最新值」，并负责写 EEPROM。

## 已知边界

- 对方**完全不运行任何程序**时收不到（机器人没有代码在跑）。要让未运行程序也能收，只能改 Android 常驻服务（高风险，需明确同意后才做）。
- 同一块板同一时刻只能跑一个用户程序（旧限制，与本积木无关）。
- 机器人 Python 3.4.5；本方案不依赖第三方库，全部用机器人自带 gcc + Android libc。

## 重新构建（维护）

```bash
# 1) 改积木/运行时后：
py -3 "WER_函数库/工具/双板通讯/构建双板通讯扩展.py"
# 2) 输出到 WER_函数库/安装包_双板通讯/（新 browser_assets.patched + 自动更新 sha 的安装脚本）
# 3) 关闭 IDE → 管理员运行 install_dual.cmd
```
