# Android 逆向与 MTK6580 工具清单（Windows）

> 核实日期：2026-11-11。版本以厂商发布页、GitHub Release API、PyPI JSON、Android SDK 仓库清单（repository2-3.xml）为准；文末列出处。
> 目标设备：MTK6580（Cortex-A7，armv7 32 位）+ Android 7，能力风暴 SKCON9，应用包名 `com.abilix.controller`。
> 标记约定：**官方** = 厂商/作者自己的发布渠道；**第三方** = 非官方镜像或社区流传包，需自行校验哈希、自负风险。

## 0. 先看结论（会改变排查顺序）

1. **USB-C 只枚举成 CH340（COM3），说明这个口不是 Android 的 USB Device/ADB 口**，而是一个 USB-串口桥：很可能接在 STM32F103 的 UART，或 MT6580 的调试 UART 上。因此 `adb devices` 为空是预期现象，不是驱动装错了。
2. 优先顺序应是：**先用 PuTTY 打开 COM3（先试 115200 8N1，再试 921600）看有没有启动日志/控制台** → 找工程模式或串口 shell 里的 adb 开关 → 仍无 ADB 时，走 **mtkclient + BROM** 直接读写 flash（MT6580 在支持列表内）。
3. **任何写 flash 之前先全分区备份**（至少 `preloader`、`boot`、`recovery`、`nvram`、`nvdata`、`userdata`）。MT6580 变砖后通常还能靠 BROM 救回，但 preloader 写错会提高救援难度。
4. 本清单里最容易被忽略、但 Windows 上 mtkclient 必需的是 **UsbDk**（不是 MTK 驱动本身）；只装 VCOM 驱动，mtkclient 仍可能找不到 BROM 设备。
5. Android 7 是 Magisk v31.1 的最低支持版本（v31 起放弃 Android 6），但 Frida 官方文档以 Android 9 为基准，Android 7 属“旧 ROM 可能可用”，要准备回退版本。

优先级：**P0 必装 / P1 需要时 / P2 可选**。

| Termux 包（python/openssh 等） | 随 `pkg` 仓库 | 官方：https://github.com/termux/termux-packages | 设备端脚本、端口转发、抓包辅助 | P2 | Android 7 已 EOL，部分新包要求更高 API；`pkg install python openssh` 先试。无 root 时不能 ptrace 其他 App、不能改系统 CA；有 root 可 `su`。 |

**Android 6/7 上跑 shell 工具的可行性**：Termux 0.118.x 是仍支持 Android 7 的官方线；基础工具（python、openssh、curl、nmap、tcpdump 需 root）可用。需要静态链接的逆向工具（frida-server、gdbserver、toybox）可直接 push 到 `/data/local/tmp` 运行；Android 7 的 `linker` 与 SELinux 会限制非系统分区执行，必要时放 `/data/local/tmp` 并 `chmod 755`。

## 8. 建议安装顺序与最小闭环

1. **离线分析先跑起来**：Platform-Tools 37.0.1 + JDK 25 + Python 3.13 venv + jadx 1.5.6 + Apktool 3.0.3 + apksigner 37.0.0。先把 `com.abilix.controller` 的 APK 拉下来（有固件/安装包即可）做静态分析。
2. **串口侦察**：装 CH340（已有）→ PuTTY 开 COM3，115200/921600 各试一次，抓完整启动日志；确认这个口到底是 STM32 还是 MT6580 的 UART。
3. **找 ADB**：串口 shell/工程模式里找 `adb`、`usb debugging`、`service.adb.tcp.port`。若能拿到 root shell：
   ```sh
   setprop service.adb.tcp.port 5555
   stop adbd; start adbd
   ```
   然后在 PC 上 `adb connect <设备IP>:5555`。USB-C 口本身大概率不能直接出 ADB。
4. **无 ADB 时的主线**：装 MTK VCOM v5.1632 + UsbDk 1.00-22 + mtkclient 2.1.4.1 → 关机进 BROM（Vol± + Power 插 USB）→ `python mtk.py printgpt` → **`python mtk.py rl backup` 全量备份** → `python mtk.py r boot boot.img`。
5. **Root**：把 `boot.img` 放到设备上，用 Magisk 31.1 修补（或先用 AIK 确认 boot 结构）→ 回刷 `boot`。MT6580 通常没有可用 fastboot，直接用 mtkclient 写。写前再备份一次 boot。
6. **动态分析**：有 root + ADB 后，push `frida-server-17.26.2-android-arm` 并以 root 启动；`frida-ps -U` 验证；再上 objection。Android 7 若异常，回退 frida 16.7.x。
7. **双板通讯**：先用 Saleae/DSLogic 抓 UART（共地、3.3V），确认波特率和协议；再用 PuTTY/Tera Term 复现；网络部分用 Wireshark/mitmproxy。不要在未确认电平前把逻辑分析仪接到 5V 线上。

## 9. 风险、合规与校验

- **变砖风险最高**：SP Flash Tool、mtkclient 写 preloader/boot、改分区表。原则：先备份（`rl backup` + 单独 `r preloader`）、电量充足、USB 2.0 直连、过程中不拔线、不选 Format All。
- **第三方包**：SP Flash Tool、MTK VCOM v5.1632 没有官方公开下载页；只从可核对哈希/签名的来源取，装前 VirusTotal + 本地杀软扫描。不要用来路不明的“一键刷机/一键 root”包。
- **杀软误报**：mtkclient 的 payload、frida-server、uber-apk-signer 常被误报；只对具体目录加排除，不要全局关杀软。
- **签名**：改包后必须重签；签名变化会导致无法覆盖安装原厂 App，且可能触发厂商完整性校验。先备份 `/data/data/com.abilix.controller`（需 root）再折腾。
- **许可**：IDA Free 仅非商业；010 Editor 商业软件；Saleae 软件免费但硬件付费；Termux GPL；Ghidra Apache-2.0。竞赛/研究用途也要遵守主办方规则。
- **合规**：只操作自己有权研究的设备；不传播厂商固件/密钥；不绕过他人设备的访问控制。
