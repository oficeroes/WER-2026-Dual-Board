## 5. 建议安装顺序（照着做就行）

1. **今天（W1/W2 用）**：Wireshark+USBPcap → 7-Zip → jadx-gui → apktool → RealTerm（可选 com0com）。
   → 目标：抓到官方软件下载的完整字节流；把 `实验11` 的自写下载跑通。
2. **W4 前（要看 .so/固件）**：Ghidra → HxD。
3. **确定要改 APK 时**：uber-apk-signer → Android command-line tools（apksigner）。
4. **确定要 root/改系统时（最后）**：MTKClient（先备份！）→ SP Flash Tool（救砖备着）→ Magisk → Frida → LSPosed。
5. scrcpy/uiautomator2 等 **adb 打通后**再装（现在装也用不上）。

## 6. 下载注意

- GitHub 在本机网络可能不稳，可用 `https://ghproxy.net/https://github.com/...` 之类镜像，但**只从官方 release 页核对文件名/哈希**，不要下来路不明的 exe。
- 所有 exe 装前看数字签名/官网域名；SP Flash Tool 只有第三方镜像，务必先备份再碰。
- 安装 Android Studio 太重（4GB+）；只要 `apksigner/zipalign` 的话装 **command-line tools**（~150MB）+ `sdkmanager "build-tools;34.0.0" "platform-tools"` 即可。
- Frida 架构：MTK6580 是 **32 位 ARMv7**，下载 `frida-server-<版本>-android-arm`；先 `adb shell getprop ro.product.cpu.abi` 确认。

## 7. 补充：工具调研子代理的核实结果（2026-11-11）

> 以下为独立调研子代理按官方发布页/GitHub API/SDK 仓库核实后的补充，**详细清单见 `_交接素材/工具清单_素材.md`**。

**必须补进"基础环境"的 4 样（不装会卡住）**

| 工具 | 版本 | 下载 | 为什么必须 |
|---|---|---|---|
| Eclipse Temurin JDK | 25 LTS（64-bit） | https://adoptium.net/temurin/releases/ | Ghidra 12.2 明确要求 JDK 25；Apktool/apksigner/jadx 也要 Java |
| Git for Windows | 最新稳定版 | https://git-scm.com/download/win | mtkclient 官方要求 `git clone` + `pip install -r requirements.txt` |
| **UsbDk** | 1.00-22 | https://github.com/daynix/UsbDk/releases/tag/v1.00-22 | **Windows 上 mtkclient 访问 BROM 必需**（只装 MTK VCOM 可能识别不到 `0x0E8D:0x0003`）；装 64 位 MSI 后重启 |
| MTK USB VCOM/Preloader 驱动 | v5.1632（第三方流传包） | https://mediatekdriver.com/mediatek-driver-v5-1632/ （MediaTek 无公开下载页） | SP Flash Tool / mtkclient 识别 Preloader；装前杀软扫描 |

**版本修正（避免下错）**

- Platform-Tools 用 **37.0.1 stable**（37.0.3 是 preview，别下）。
- jadx **1.5.6**（选 `jadx-gui-1.5.6-with-jre-win.zip` 最省事）；Apktool **3.0.3**；apksigner 用 build-tools **37.0.0**。
- Frida **17.26.2** + frida-tools **14.13.1**，server 资产 `frida-server-17.26.2-android-arm.xz`（**32 位 arm**）；Android 7 若异常回退 frida 16.7.x。
- Magisk **31.1**（v31 起最低 Android 7.0，本机刚好支持）；mtkclient **2.1.4.1**（MT6580 在支持列表）；Ghidra **12.2**；scrcpy **5.0.1**；uber-apk-signer **1.3.0**；Termux **0.118.3**（F-Droid，Android 7.0+）。
- SP Flash Tool **v5.2136**、MTK VCOM v5.1632 只有第三方来源：只用 **Download Only**，**绝不 Format All**，装前校验哈希。

**排查顺序修正（重要，优先于本文 §5 的顺序）**

1. 先 **PuTTY 打开 COM3**（先 115200 8N1，再试 921600）→ 看这个口是 MT6580 调试 UART 还是 STM32 的 UART，有没有启动日志/控制台/shell。
2. 找工程模式/串口 shell 里的 adb 开关：能拿到 shell 就可 `setprop service.adb.tcp.port 5555; stop adbd; start adbd`，再 `adb connect <机器人IP>:5555`（这比刷机安全得多）。
3. 无 ADB 才走 **mtkclient + BROM**：关机 → 按住 Vol± + Power 插 USB → `python mtk.py printgpt` → **`python mtk.py rl backup` 全分区备份** → 再谈 root/写分区。
4. 有 root + adb 后：push `frida-server` 到 `/data/local/tmp/`、`chmod 755`、root 运行；Android 7 注意 SELinux/ptrace 限制。

**可选但有用（逻辑分析仪）**：Saleae Logic 2（软件免费）或 DSLogic+DSView，用来看 UART（共地、3.3V、先确认电平），对"这个 COM3 到底接 MT6580 还是 STM32""端口 12 路 UART 复用"很有帮助。

## 8. APK 侧新证据带来的补充（2026-11-11 晚间）

> 详见 `_交接素材/APK证据_素材.md`。以下主要是**已有工具的新用法** + 一个关键资源。

| 项 | 说明 |
|---|---|
| **AOSP testkey（关键资源）** | 公开的 `testkey.pk8` + `testkey.x509.pem`：从 AOSP 源码 `build/target/product/security/` 获取（`git clone https://android.googlesource.com/platform/build`，或网页 https://android.googlesource.com/platform/build/+/refs/heads/master/target/product/security/ ）。用途：签一个能和 `AbilixSetting` 共享 `android.uid.system` 的更新包（**高风险实验，先备份官方 APK 并征得用户同意**） |
| apksigner 签 testkey 包 | `apksigner sign --key testkey.pk8 --cert testkey.x509.pem --out signed.apk app-unsigned.apk`（v1+v2 都开，兼容 Android 7） |
| androguard（pip） | `pip install androguard==4.1.4`：读 APK 证书/清单（本轮就是用它确认 testkey 指纹的） |
| 8890 测试 | **不需要新工具**：Python 标准库 socket 即可（帧 `AA 55`；见交接文档 §0.4 第 6 条） |
| TransSerial 测试 | PuTTY/RealTerm 开 COM3 @ **1,000,000 8N1**，手发 `55 55 11` 看回 `0x61`/`0x65`（与 937500 AA55 对照） |
| 建议顺序调整 | 先做 8890 无鉴权投递（零风险）→ 再评估 testkey 换 Setting（高风险，需用户同意）→ root/刷机（最后手段） |
