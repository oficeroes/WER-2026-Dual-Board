## 0. 实验顺序（建议严格按此顺序）

| 序 | 实验 | 器材/接线 | 时间 | 判活标准（通过条件） | 不通过时的下一步 |
|---|---|---|---|---|---|
| A | **实验05 环境探测** ✅已做（2026-11-10） | 一板，无需接线 | 10 min | 实测 **socket=0**（`No module named '_socket'`）；time/sys/os/threading/struct/json 可用 | **WiFi 纯 Python 路线已关闭** → 做 B/E；另走 USB-C 有线（实验09） |
| B | **实验01 声音链路** | 两板，无需外设 | 15 min | B 屏 `get_mic` 随 A 播放出现明显起伏 | 若读数无变化：检查音量/距离/环境噪声；仍不行 → E |
| C | **实验08 WiFi TCP** | 两板 + 同一 2.4G 路由器（或 A 热点） | 20 min | B 收到 A 的 `ACK`（屏幕可见） | 检查 IP/AP 隔离/防火墙；失败不影响 D/E |
| D | **实验02 端口单线** | 自制两针线（先做 `00_接线与安全测量.md` §3.5 单板自环） | 40 min | B 的 `get_ai/get_touch` 随 A 的 `set_do` 跳变 | 空置端口读不到 → 需传感器仿真兜底，或放弃该路线 |
| E | **实验03 光链路** | 彩灯/智能灯 + 光敏（或颜色光敏/灰度） | 30 min | B 光强读数随 A 灯亮灭明显变化 | 调距离/遮光/换接收传感器 |

## 1. 实验 A：环境探测（先回答"能不能走 WiFi"）

1. 下载 `实验05_运行环境探测.py` 为 `ProgramC`（或任意名，记得改文件头）到任意一块板；
2. 运行，等屏幕打印 `done`；
3. 记录：`socket=` 的值、各 `模块名=0/1`、`py=` 版本；
4. 结果已同时写入 EEPROM 100~115（掉电不丢），可运行 `实验05b_环境探测结果读回.py` 再读。

更全面的探测程序（推荐）：`../../_分析临时/研究证据/运行环境/探测_import与环境.py`（ProbeEnv，探测 24 个 stdlib 模块 + socket 能力 + 本机 IP + threading + 文件可写性，结果写 EEPROM 1~74）+ `读回_EEPROM结果.py`。

**判定**：
- `socket=2` → WiFi 路线成立，做实验 C（最佳方案）；
- `socket=1`（能创建但 bind 失败）→ 还是可以做客户端（主动连 PC/另一板），做实验 C 时让 B 当客户端、A 跑 PC 中继；
- `socket=0` → 放弃 WiFi 方向，做 B/E。

## 2. 实验 B：声音链路（最先能看到"两板通讯"效果）

1. 两块板分别下载 `实验01_声音链路_发送端A.py`（ProgramA）与 `实验01_声音链路_接收端B.py`（ProgramB）；

## 3. 实验 C：WiFi 两板 TCP（❌ 已实测不可用，作废；仅留作历史）

> 2026-11-11 更新：实验05 实测 `socket=0`（无 `_socket` 模块）→ 纯 Python 无法建 TCP，本实验**作废**。
> 若以后 C 用户程序能直接用 libc socket（见交接文档 W4），再改为 C 版重做。

1. 组网：两板都连同一 2.4G 路由器（路由器关闭"AP 隔离/客户端隔离"），或 A 开热点、B 连 A 热点；
2. 查 IP：机器人「设置→WLAN」界面 / 路由器 DHCP 列表 / 用 PC 扫描（`Test-NetConnection <IP> -Port 10086`）；
3. A 板下载 `实验08_WiFi两板_TCP_服务端A.py`（ProgramA）并运行，屏幕显示 `listen 12345`；
4. B 板下载 `实验08_WiFi两板_TCP_客户端B.py`（ProgramB），把 `A_IP` 改成 A 板真实 IP，运行；
5. 判定：A 屏出现 `client (...)`+`RX1: hello 1`，B 屏出现 `TX 1 ok`+`RX: ACK1:hello 1` → 双向通讯成立。
6. 进阶：测延迟（B 端用 `robot.reset_timer/get_timer_ms` 包住 send/recv），记录 20~100ms 量级是否符合。

> 更完整样例（含线程、UDP 发现 IP、PC 中继）在 `_分析临时/研究证据/运行环境/`。

## 4. 实验 D：端口单线（方向1 的物理实现）

> **安全第一**：先读 `00_接线与安全测量.md`；**禁止**普通 RJ11 直通线对插；先做单板自环。

1. **单板自环（零风险）**：同一块板，把端口 X 的 SIG 用杜邦线（串 1kΩ）接到端口 Y 的 SIG，共 GND；跑 `实验02` 的发送端（改 PORT=X）和接收端（改 PORT=Y，MONITOR 模式）——先证明"空置端口能读外部电平"，并测往返时延；
2. 若自环 OK：两板按 `00_接线与安全测量.md` 自制两针线，A 发送端 PORT=1，B 接收端 PORT=1；
3. B 先 MONITOR：A 手动用发送端发慢速脉冲，看 `ai`/`touch` 是否跳变；
4. B 改 DECODE（阈值 `THR` 取 A 高/低读数的中间值），A 发 `MSG`，看 B 解出的 0/1；
5. 记录：`BIT_DT` 从 0.1s 逐步降到 0.05/0.03/0.02/0.01，记录各档成功率 → 得到实际可用速率。

**判定**：空置端口 `ai` 恒定不变（例如一直是 0/4095 不动）→ 端口被传感器识别机制"按住"，需要兜底（信号线加 NPN/光耦拉低模拟碰撞传感器），或该路线在你的固件版本上不可用。

## 5. 实验 E：光链路（方向2 的可控版本）

1. A 板：彩灯/LED（DO 口）或智能灯，下载 `实验03_光链路_发送端A.py`，`MODE='do'` 或 `'smart'`；
2. B 板：光敏/颜色（光敏模式）插 PORT 口，下载 `实验03_光链路_接收端B.py`，先 `MODE='monitor'`；
3. 摆放：A 的灯正对 B 的传感器，距离 0.5/1/3/5/10cm 逐档测；避免环境强光直射；
4. 记录 MONITOR 读数在"灯亮/灯灭"两种状态下的值 → 填 `THR_ON/THR_OFF`，改 `decode` 复测；
5. 同理可换 `SENSOR='gray'`（灰度）或 `'ai'`（通用模拟）试。
