# 实验21 · 电脑打字上屏（PC → 机器人屏幕）

> 目标：打开一个网页（打字网站），在网页上打的任何字，实时显示在 SKCON9 主板的机身屏幕上。

## 组件

| 文件 | 运行位置 | 作用 |
| --- | --- | --- |
| `PCTEXT.c` | 机器人（2 号机 192.168.1.103） | TCP 服务器 `0.0.0.0:9001`，收到文字后用 `Clear()` + `Printf()` 显示到机身屏幕 |
| `pc_typing_server.py` | 电脑（192.168.1.105） | 本机网页服务 `127.0.0.1:8000`，把网页文字转发给机器人 9001 |
| `typing.html` | 电脑浏览器 | 打字页面（大字输入框 + 屏幕预览 + 连接状态） |
| `启动打字演示.cmd` | 电脑 | 一键启动桥服务并自动打开网页 |

## 使用步骤

1. **机器人端（只需做一次）**：在机器人屏幕的程序列表里运行 `PCTEXT.c`。
   - 屏幕上出现 `PCTEXT ready / port=9001 / listening :9001` 表示就绪。
   - 程序会一直监听，电脑连上来时屏幕显示 `PC connected`。
2. **电脑端**：双击 `启动打字演示.cmd`，会自动打开 `http://127.0.0.1:8000/typing.html`。
3. 在网页大输入框里打字 → 机器人屏幕同步显示。
   - 右上角状态点变绿 = 机器人已连接。
   - 按 `Esc` 或「清空 / 清屏」按钮 = 清空文字并清屏。
   - 「追加模式」= 每次输入的内容作为新的一行往下加（适合留痕展示）。

## 通信协议（PCTEXT 行协议，UTF-8）

| 命令 | 含义 |
| --- | --- |
| `T <text>` | 清屏后整屏显示 `<text>`（默认，打字同步用） |
| `A <text>` | 追加一行显示 |
| `C` | 清屏 |
| `Q` | 退出程序 |

## 排错

- 网页右上角红点、提示「未连接」：确认机器人上 `PCTEXT.c` 正在运行；确认电脑与机器人同一 WiFi（当前 PC=192.168.1.105，机器人=192.168.1.103）。
- 屏幕没有任何字：先看机器人屏幕是否显示 `PCTEXT ready`；若显示 `ERROR: ...`，把屏幕上的 gcc 报错拍下来。
- 端口占用：PCTEXT 退出后立刻重开可能提示 `bind fail`，等几秒再运行。
- 机器人同一时刻只能运行一个用户程序：运行 PCTEXT 会顶掉正在跑的其他程序，属正常。

## 原理说明

- 机器人的 Python 运行时没有网络能力（`_socket` 缺失），但 **C 用户程序可用 libc socket**，所以接收端用 C 写。
- 网页 JS 不能直接开 TCP，因此电脑侧需要一个极小的本地桥（`pc_typing_server.py`），浏览器→桥用 HTTP，桥→机器人用 TCP。
- 机器人屏幕文字输出：C 侧 `Printf()`（经 `Robot.h` 的 `#define printf Printf`）；C 程序入口必须是 `int Main(...)`（`libRobot.so` 通过 `dlsym("Main")` 加载用户代码）。
